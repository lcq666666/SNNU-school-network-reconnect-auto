## 2. 阶段 0：工程与分支准备（F22 前置）

**目标**：建立可协作、可回滚、可离线验证的工程基线。本阶段不修复任何 F 编号缺陷。

### 任务 0.1 解决远端分支授权并推送开发分支

- 现状：本地分支无 upstream；GitHub 集成令牌只读（写操作 403）；本机 git 默认代理会拦截 github.com。
- 操作：用户提供 PAT 或配置 SSH 后，按本机约定**清空代理环境变量**再推送：
  ```bash
  http_proxy= https_proxy= HTTP_PROXY= HTTPS_PROXY= git push -u origin fix/reconnect-stability-20261013
  ```
- 推送后核对 upstream 为 `origin/fix/reconnect-stability-20261013`，确认不会误推 `main`。
- 禁止：写入或输出访问令牌；全局关闭用户代理；force push。

### 任务 0.2 搭建隔离开发环境

- 新建项目 venv（不使用全局环境装依赖），安装运行依赖 `requests keyring pystray pillow` 与开发依赖 `pytest pytest-cov ruff`（版本范围在阶段 1 锁定）。
- 开发/调试一律用 venv 内的显式 python 路径，避免与系统 Python314 混淆（F21 相关）。

### 任务 0.3 建立依赖清单骨架

### 任务 0.4 提交工作树清理规则

## 3. 阶段 1：回归测试基线与共享契约（对应《审查方案》阶段 A）

### 任务 1.1 建立离线 pytest 骨架与 fake adapters

- 新增 `tests/conftest.py`，提供可注入的假件，覆盖全部 Windows/网络副作用点：
  - `FakeRegistry`：模拟 `winreg` 打开/查询/设置/删除，可编程注入 `PermissionError`（查询拒绝、写入拒绝）与句柄行为；
  - `FakeKeyring`：模拟凭据后端，可注入"第一条成功/第二条失败""读取抛异常"；
  - `FakeSession`/假 transport：按脚本返回响应（状态码、头、正文、编码），不产生真实连接；
  - `FakeLauncher`：记录 Edge 启动调用，不真实启动进程；
  - `VirtualClock`：可推进的单调时钟，替代 `time.monotonic`/`sleep`，禁止测试真实 sleep 三分钟。
- 约定：测试不 import 并运行 `main()`；不读取真实凭据；默认集合零真实 I/O。
- 建议目录：`tests/unit/`（纯逻辑）、`tests/regression/`（F 编号回归）、`tests/fixtures/`（脱敏响应样本：GB2312/UTF-8/验证码页/错误页）。

### 任务 1.2 定义共享契约与错误码（`campus_core.py` 草案）

## 4. 阶段 2：稳定性与系统副作用止血（对应《审查方案》阶段 B）

### 任务 2.1 修复代理注册表读写与端点验证（F04 + F05）

- 位置：`campus_reconnect_tray.py` `set_system_proxy()` 第 119–137 行。
- 实现要点：
  1. 先用具备 `KEY_QUERY_VALUE` 的句柄读取完整快照（ProxyEnable/ProxyServer/ProxyOverride/AutoConfigURL），再决定是否修改；读写句柄申请 `KEY_QUERY_VALUE | KEY_SET_VALUE`，不得在只有 SET_VALUE 的句柄上 `QueryValueEx`。
  2. 端点验证：默认**不**启用联动；显式确认目标地址并保存授权对应端点，不硬编码猜测 `127.0.0.1:7897`（CLASH_SERVER_DEFAULT 仅在用户显式确认时作为建议值展示）；地址须为允许的本地端点并做 TCP 监听探测；无法验证时不改代理并提示。
  3. 顺序约束：验证端点与必要配置全部通过后，**最后**才写 `ProxyEnable`；保留既有 PAC（AutoConfigURL）与其他代理配置，不 fabricate ProxyServer。
  4. 失败处理：任一写入失败执行针对本次变更的回滚，回滚失败单独明示；调用 `InternetSetOptionW` 刷新并检查返回值；注册表写成功不等于所有应用立即采用，通知文案不得夸大。
- 结果对象：返回结构化结果（是否变更、修改项、原值/新值、错误码），供托盘通知与日志使用。

### 任务 2.2 修复配置校验与原子持久化（F03 + F13）

- 位置：`campus_reconnect_tray.py` `load_config()`/`save_config()` 第 68–82 行、设置面板 `on_save()` 第 468–488 行；引擎第 54、75–87 行。
- 实现要点：
  1. `load_config()` 改走阶段 1 的 `Config` 验证器；非法配置产生可见错误提示与安全默认值；未知键隔离 + 脱敏告警。
  2. 数据目录默认 `%LOCALAPPDATA%\CampusReconnect\`；便携模式（exe 同级）必须显式且可写；首次从旧位置迁移时只读校验并保留旧文件，不静默移动/删除，不把旧配置"凭据化"。
  3. 原子保存：同目录临时文件 → 写入 → flush/fsync → `os.replace`；失败保留旧文件并向用户明示，不得显示"已保存"。
  4. 日志初始化失败可降级并给出可见错误，不得在 UI 出现前静默崩溃（对应 T37 只读目录场景）。

### 任务 2.3 重连排他与工作线程监督（F01 + F02）

- 位置：托盘 `repair_once()` 第 192–221 行、`on_reconnect()` 第 332–342 行、`monitor_loop()` 第 275–318 行。
- 实现要点（第一阶段止血，队列化允许在本阶段先用 lock 落地）：
  1. 单网络工作线程独占一个 Session；手动、自动、启动检查都通过命令队列下发；重复手动请求合并并提示"正在重连"，不得每点击一次新建线程。
  2. 每个任务持有不可变配置快照 + 操作 ID + 配置版本；过期结果不得覆盖新状态；UI 线程不得持锁等待网络。
  3. 工作单元整体异常边界：`monitor_loop` 内任何异常（int 转换、repair、结果处理）转换为可识别内部错误状态，清理 busy，受限重试；主线程保存工作线程句柄与最近心跳；线程意外退出时 UI 明确显示"监测已停止"并提供重启动作；预期认证拒绝（如密码错误）不当作内部异常。
- 验收对应：T01/T02/T03/T04。

### 任务 2.4 取消令牌、凭据存储与授权版本（F10 + F11 + F12）

- F10（暂停/退出约束）：为 stop/pause/配置版本建立取消令牌；阶段间与任何副作用（POST、Edge、代理写入）前重新校验；等待改可唤醒 Event；后台线程不得直接调用 Tk，改用 Tk 侧轮询消费队列；保存并取消启动 Timer；有界异步 shutdown，主线程不长时间 join。明确"暂停后手动重连"规则（默认不启动新认证，用户主动重连需单独确认）。
- F11（凭据）：封装 `CredentialStore`，显式选用并验证 Windows 安全后端；返回未配置/访问失败/读写失败等可区分结果；两条写入（username/password）的部分失败要尝试恢复旧对并明确提示；GUI 启动捕获写入错误；新增"更新账号/密码""清除凭据"入口；失败保持应用可见而非崩溃；不记录/序列化含密码对象（与 T22/T34 对应）。
- F12（授权）：consent 三态（未知/同意/拒绝）明确区分并绑定端点与版本；同一时刻只允许一个询问，由 Tk 主线程管理；过期请求结果不应用，新拒绝/撤销始终优先；设置保存只提交用户实际变更项；自启项不属于当前安装时不静默接管，先确认（与 T23/T24 对应）。

## 9. 质量门禁与工程约束

1. 每个提交前本地运行默认离线测试集与 `ruff check`，全绿才提交；提交只含明确列出的文件。
2. 默认测试集：零真实网络、零真实注册表、零真实凭据、零真实浏览器启动；违反即视为测试缺陷。
3. 关键路径（认证判定、重定向、代理写入、冷却）必须有用例；纯逻辑分支覆盖率 ≥ 85%。
4. 日志与通知：结构化错误码 + 操作 ID + 阶段 + 耗时；不记录 body、完整账号、密码、Cookie。
5. 不在本计划内混入大规模重命名、美化、依赖大版本升级与二进制更新。

## 10. 风险与禁令（全程有效）

- 不主动执行 Portal 注销；不用踢会话方式测试恢复。
- 核心探测与登录保持 `trust_env=False`；文档需说明这不绕过 TUN/路由层代理。
- 凭据只留在 Windows 凭据管理器；不改为 JSON/环境变量/云端/日志。
- 真实 Portal 与系统级测试仅在用户授权后按 5.2 执行。
- 不自动修改 Clash 配置、订阅或 TUN 设置。
- 不覆盖 v0.1 产物；不 force push；不跳过检查直接合并。

## 11. 提交、合并与回滚

- 分支：全程在 `fix/reconnect-stability-20261013` 小步提交；不直接推 main。
- PR：列问题编号、验收证据、未解决风险、版本兼容与迁移行为；CI 全绿后请求审阅。
- main 有新提交时先审查差异再整合，不强制 reset 覆盖本地。
- 回滚：优先 `revert` 新增提交；配置保留 schema 迁移兼容与原文件备份；回滚不得删除用户凭据或强行恢复注册表快照覆盖其他软件新设置。
- 推送：本机 git 先清空代理环境变量再 `git push`；GitHub 集成令牌只读，不能用于推送/建分支，需 PAT 或 SSH。
