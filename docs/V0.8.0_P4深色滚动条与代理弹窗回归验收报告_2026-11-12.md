# V0.8.0 P4 验收报告：深色滚动条样式与代理弹窗主题回归

- 日期：2026-11-12
- 分支：`ui/p3-editorial-pages`（基于 P3 `2eea54a`）
- 范围：P4 两项——深色滚动条主题化、代理弹窗深色完整回归。仅呈现层，不动算法与状态机。

## 背景

P3 交付后遗留两项呈现层收尾（见 `.impeccable.md` 与工作日志）：

1. **深色滚动条**：`CTkScrollableFrame` 内部创建的 `CTkScrollbar` 默认跟随 CustomTkinter 的 dark/light 配色，与本项目自定义的深墨 / 暖纸 token 不一致，滚动条在深色下偏亮、不协调。
2. **代理弹窗深色回归**：`campus_proxy_ui.open_dialog` 在 P1 已接入 token，但缺少深浅切换下的完整回归断言，无法证明弹窗所有控件（窗口底色、面板、按钮、下拉框、文本框、滚动条）都跟随主题。

## 交付内容

### 深色滚动条主题化（`campus_desktop_ui.py`）

- 三套配色（`_LIGHT` / `_DARK` / `CONSOLE`）各新增滚动条 token：`SCROLL_TRACK`（轨道）、`SCROLL_THUMB`（滑块）、`SCROLL_HOVER`（滑块悬停）。取值低饱和、与各自底色协调，键集与既有 token 一致。
- `_paint` 新增 `scrollbar` 角色，供显式绑定的滚动条重绘。
- `apply_theme` 在递归遍历时直接识别 `CTkScrollbar` 并按当前配色着色——因为 `CTkScrollableFrame` 内部滚动条没有 `_campus_theme` 标记，必须靠遍历命中。
- `page()` 创建 `CTkScrollableFrame` 时直接传入滚动条颜色，保证**首屏**即正确，而非等主题切换才更新。
- `configure_theme` 补 `TScrollbar` 的 ttk 原生样式兜底，覆盖 shell 中可能出现的原生滚动条。

### 代理弹窗滚动条（`campus_proxy_ui.py`）

- `open_dialog` 的 `CTkScrollableFrame` 同样传入三色滚动条 token，深浅主题下弹窗滚动条一致。

### 测试

- `tests/unit/test_v080_ui_theme.py` 新增 2 项：滚动条 token 键集在三套配色一致；滚动条颜色随主题切换在浅/深间正确变化。
- `tests/unit/test_v069_proxy_compat.py` 新增 1 项 `test_proxy_dialog_follows_dark_theme_repaint`：代理弹窗在浅色基线、切深色、再切回浅色三态下，窗口底色、文本框、主/次按钮、面板、下拉框、滚动条全部断言跟随对应 token，无控件滞留于错误主题。
