## 1. 执行摘要

项目已经具备真实场景下的重连闭环、动态认证端口、Windows 凭据保存、CLI/托盘入口、开机自启、日志和用户文档，适合作为后续迭代基础。建议保留现有技术栈，不大规模重写，不引入后端或云端凭据存储。

当前最需要处理的不是界面美化，而是以下六类问题：

1. 托盘自动重连与手动重连可以并发，共用 HTTP Session，可能重复认证并覆盖状态。
2. 托盘监测线程在重连或配置异常时可能直接退出，但托盘图标仍留在任务栏，形成“看起来运行、实际上不再保护”的状态。
3. 代理联动先启用系统代理，再用缺少查询权限的注册表句柄读取代理地址，存在**操作报失败但设置已改变**的确定性缺陷。
4. 非法配置未经校验，保存失败被吞掉；字符串 `"false"` 可能被当作同意代理联动。
5. 登录成功判断只用正文子串，没有校验响应状态、页面来源与账号字段；网络探测失败也没有区分认证失效和 DNS/探测站点故障。
6. 两个入口的冷却逻辑不一致：CLI 可被短暂恢复绕过冷却，托盘则整个冷却期间停止探测；手动重连还可绕过自动路径的限制。

本文列出 **24 项问题**：12 项 P1、10 项 P2、2 项 P3。没有把未实测的安全风险包装成“已经发生的凭据泄露”，也没有把历史上已修好的问题重复列为当前缺陷。

建议分阶段交付：**回归测试基线 → 线程/配置/代理止血 → 共享重连引擎与状态分类 → Windows 兼容与发布规范**。

## 5. P1 问题：定位、修复与验收

### F01 自动/手动重连并发

**定位**：托盘第 192–221、275–317、332–342、514–521 行。

`on_reconnect()` 每次点击都创建新线程；监测线程可以同时调用 `repair_once()`；启动通知还使用相同 `self.session`。没有 repair 锁，也没有工作队列。`cfg = self.config` 只是别名，不是快照。

**触发/影响**：掉线时连续点击“立即重连”，或自动流程执行中修改账号运营商；请求可能交叉、Cookie/状态互相影响、重复认证、多个授权弹窗与通知乱序。刚启动时手动点击还可能在 `session is None` 时调用探测。

**修复**：一个网络工作线程独占一个 Session；手动、自动、启动检查都发送命令给它。引入 `repair_in_progress`/锁作为第一阶段止血，随后统一队列；重复手动请求合并并提示“正在重连”。每次任务持有不可变配置快照、操作 ID 和配置版本；拒绝过期结果覆盖新状态。不要在 UI 线程持锁等待网络。

**验收**：用 barrier 同时触发自动流程与 10 次手动请求，最多一个认证任务在途；不会额外创建 10 个网络线程。任务中更改运营商不改变本次请求；启动未完成时手动操作不抛异常。

### F02 监测线程异常退出而托盘仍存在

**定位**：托盘第 283–317 行，尤其 288、301、304、314–317 行。

`try/except` 只包探测；`int(cfg[...])`、`repair_once()`、`_after_repair()` 均可能异常并离开线程。`start()` 不保存工作线程句柄，也没有心跳检查。

**修复**：为整个工作单元设异常边界，转换为可识别内部错误状态，清理 busy 标志并保持受限重试；配置错误应先规范化，不能靠无限 `except` 掩盖。主线程记录工作线程对象与最近心跳；线程意外退出时明确显示“监测已停止”并提供重启动作。预期认证拒绝不能被当作内部异常。

**验收**：mock 让端口解析、凭据读取、重连结果处理分别抛错；线程不静默失效，UI 可查看具体故障，后续合法命令仍可处理。

### F03 配置类型与用户授权不校验

**定位**：托盘第 68–74、235、288–317 行。

`cfg.update(json.loads(...))` 直接接受任意键值。`interval="bad"` 后续转换失败；`clash_auto_proxy="false"` 是非空字符串，`if allow` 为真。

**离线证据**：原 `load_config()` 接受 `{"interval":"bad","clash_auto_proxy":"false"}`；输出分别为字符串 `bad`、字符串 `'false'`，布尔转换结果为 `True`。

**修复**：新增 `Config` 模型与 `schema_version`；顶层必须是对象。数值只接受真正整数（显式排除 bool），范围统一；开关只接受 bool，代理授权仅接受 `None/True/False`，缺失/无效授权必须不启用代理。未知键隔离并记录脱敏告警。非法配置回退要告知用户，不能静默恢复自动操作许可。

**验收**：覆盖 JSON null/list、字符串开关、负数、小数、超大值、未知版本；错误输入不能开启代理，不能让监测线程死亡。

### F04 代理注册表权限与部分写入

**定位**：托盘 `set_system_proxy()` 第 119–137 行。

仅用 `KEY_SET_VALUE` 打开句柄，却在第 129 行 `QueryValueEx`，没有 `KEY_QUERY_VALUE`；且第 125 行先把 `ProxyEnable` 改成 1。读取权限失败后外层捕获 `OSError` 返回 False，但前面的修改已经完成。

**离线证据**：模拟查询被拒绝时，原函数返回 `False`，而假注册表 `ProxyEnable` 已经从 0 变成 1。

**修复**：先以查询权限读取完整快照，再判断是否允许修改；需要读写的句柄申请 `KEY_QUERY_VALUE | KEY_SET_VALUE`。先验证端点和必要配置，最后才启用。写入异常进行针对本次变更的回滚，回滚失败单独显示，不能继续宣称保持原状。配置更新后调用适当的 Windows 设置刷新/通知机制并检查返回值；注册表写成功不等于所有应用立刻采用新值。

**验收**：查询拒绝、任一写入拒绝、刷新失败、回滚失败均有清晰结果；未完成验证不得改变 `ProxyEnable`。先 mock 验证，真实注册表测试必须由用户明确批准并备份相关项。

### F05 启用不存在或错误的系统代理

**定位**：托盘第 47、119–137、235–239 行。

缺少 `ProxyServer` 时硬编码 `127.0.0.1:7897`；有值时也不确认它属于用户预期的代理、进程是否在监听。用户同意“Clash 联动”并不等于同意任意历史系统代理。

**影响**：Portal 与直连探测已经恢复，但浏览器被切换到未运行代理，形成“通知说成功、实际不能正常浏览”的体验；还可能误启用其他软件留下的代理配置。

**修复**：默认联动不启用。显式确认目标地址，保存授权对应的端点，不自动猜测端口；检查地址为允许的本地端点、监听/基本健康状况，并保留现有 PAC 与其他代理配置。TCP 可达只能说明监听，不足以证明一定是 Clash。端点变化需重新确认；无法验证时不修改代理并给出提示。

**验收**：Clash 未运行、端口变更、多协议代理值、其他代理配置、代理关闭均覆盖；网络恢复成功与代理联动失败是两项独立结果。

### F06 登录成功判定过宽

**定位**：引擎 `portal_login()` 第 278–302 行，特别是 297 行。

仅判断 `ONLINE_MARKER in body and account in body`。没有校验最终 HTTP 状态、最终 URL、确切账号字段或页面类型；账号子串可误匹配其他账号，登录表单回显也可能误导。已有会话返回状态页时，不能据此证明本次新密码有效。

**离线证据**：假响应为 HTTP 500、正文 `当前登录账号 1234567`，提交账号 `123456`，原函数仍返回成功。

**修复**：解析明确的状态页账号字段，规范化后完整比较；要求可信目标、允许状态码与确切页面结构。区分 `ALREADY_AUTHENTICATED` 与本次认证成功。先获取已有状态，自动模式在线则不 POST；`--force` 明确说明不能依靠已有会话验证新凭据。错误文字仅在已识别错误区域提取，避免导航脚本中的“失败/绑定”等词触发错误分类。

**验收**：500+在线文字、账号前缀、表单回显、其他账号、GB2312 状态页、已有会话+错误密码、验证码页均不误报本次认证成功。

### F07 凭据请求的自动重定向与 HTTP 边界

**定位**：引擎第 58、120–127、283、292–293 行。

Portal URL 为 HTTP；认证 POST 使用 `allow_redirects=True`，没有目标白名单。Requests 遇到某些 307/308 重定向时可保留方法与请求体；因此恶意或错误的目标可能收到表单凭据。移除 Authorization 头并不能保护位于 POST 表单中的密码。

**性质**：缺少目标验证已确认；本次没有测试校园网络劫持，也没有证据表明凭据已经外泄。HTTP 缺少链路机密性/服务端认证是学校系统限制，白名单不能阻止链路层中间人。

**修复**：认证 POST 禁止自动跳转，逐跳检查绝对化后的 scheme、host、port、path、最大跳数。只允许明确的 Portal 流程；正常 302/303 结果以不带凭据的 GET 获取状态页。307/308 默认拒绝自动重放凭据；跨 origin 一律拒绝。访问登录表单、识别验证码与流程变更后才取凭据并提交。HTTPS 若学校确实支持则验证证书，不能猜测切换 URL，也不能设置 `verify=False`。

**验收**：302、303、307、308、相对 URL、跨 host/port、循环跳转全部 mock；未允许目标收到的凭据请求数必须为 0。网络/报告/日志中不得记录密码或 Cookie。

### F08 网络状态与认证状态混同

**定位**：引擎第 106–116、348–369、457–474 行；托盘第 293–317 行。

探测为两地址顺序尝试、首个成功即返回；`Success` 子串过宽。两站点故障、DNS 异常、公网部分受限都会导致认证重试。`portal_reachable()` 仅证明收到 2xx/3xx，不能证明账号已掉线。Portal 已在线但公网未通会在后续循环再次登录。

**修复**：引入 `ProbeResult/PortalStatus`，保留每个探测的 HTTP/超时/DNS/重定向信息。探测严格匹配预期响应结构，增加独立可配置的 HTTPS 诊断，但保留 captive portal 检测能力。失败达到阈值后读取只读状态页，先区分：非目标网络、Wi-Fi 断开、Portal 不可达、认证失效、已认证但公网异常、探测不可信。只对明确需要登录的状态发 POST；未知结构报告“无法确认/疑似改版”，不能保证一定是改版。

**验收**：探测地址单点失败、两点受限、200 captive HTML、DNS 故障、Portal 已认证但公网故障均不会无休止重登。公网可用只代表连通性，不自动证明经过 SNNU 路由；多网卡场景需另行验证。

### F09 冷却不统一，手动操作可绕过

**定位**：引擎第 454–474 行；托盘第 314–317、332–342 行。

CLI 探测一次通过即 `next_attempt=0`，会清掉上次尝试的冷却；若 repair 抛错，冷却更新还会被跳过。托盘在成功和失败后都等待完整 cooldown，期间不再探测，也不及时响应参数和恢复；手动线程没有共同 deadline。

**离线证据**：虚拟时钟、`threshold=1/interval=15/cooldown=180`，失败→成功→失败序列中原 CLI 在 0 秒和 30 秒各尝试一次。

**修复**：共享 `last_attempt/next_attempt_at` 与单调时钟，开始认证前登记，在 `finally` 保证更新；恢复不抹掉最短间隔。cooldown 仅禁止新的认证，不禁止探测、UI 命令和只读诊断。密码错误/冻结等进入需用户处理状态，禁止自动频繁重试；网络故障指数退避并设上限，成功稳定后才重置退避。手动重连默认遵守限制，任何“强制绕过”必须单独说明和确认。

**验收**：短暂恢复、异常、同时手动/自动均满足最短间隔；冷却中恢复能在下一轮探测发现，不等待三分钟才刷新状态。用虚拟时钟测试，不真实 sleep 三分钟。

### F10 暂停/退出不能限制后续副作用

**定位**：托盘第 215–216、249–260、344–348、384–393、507–516 行。

验证阶段使用 `time.sleep()`，暂停只改变配置，退出没有等待网络线程；启动 Timer 未保存/取消。重连中的线程仍可能在退出之后打开 Edge、弹授权或改代理。后台线程调用 `root.after()` 还可能与 Tk 销毁竞争。

**修复**：stop、pause、配置版本形成取消令牌，阶段间及任何副作用前再次校验。等待改为可唤醒的 event；网络请求有有限 timeout，正在阻塞的同步 Requests 调用不承诺即时可取消，但完成后必须丢弃过期结果。Tk 主线程轮询 UI 事件队列，不从网络线程调用 Tk；保存并取消 Timer，使用有界异步 shutdown，不在主线程长时间 join。明确“暂停后手动重连”规则，建议默认暂停时不启动新认证，用户主动重连可单独确认。

**验收**：阶段中 pause/quit 后不得启动下一次 POST/Edge/代理写入。已在途 POST 无法撤回，UI 应明确；退出不遗留可再次执行副作用的工作线程。

### F11 凭据写入部分失败与错误混同

**定位**：引擎第 208–214、264–275 行；托盘第 571–579 行。

用户名和密码分别调用 `set_password()`，第二次失败没有恢复第一条；GUI 启动没有捕获写入错误。读取时所有异常都变成 None，用户看到“未保存凭据”而不是凭据库不可访问。仅弹出首次输入，修改密码需手动删除系统记录，容易操作错。

**修复**：封装 `CredentialStore`，显式选用并验证 Windows 安全后端；返回未配置/访问失败/读写失败等结果。保留兼容的 service 名，不自动搬入明文配置。写入前检查旧对、必要时用内存恢复；两条写入不存在天然事务，回滚失败必须提示。添加“更新账号/密码”“清除凭据”入口；失败保持应用可见而非崩溃。不得记录或序列化含密码的数据对象，支持 `repr=False` 或专门秘密容器。

**验收**：第一次/第二次写入失败、读取异常、更新中断、清除取消、无凭据首跑均覆盖。所有测试使用假凭据后端，不删除用户现有记录。

### F12 过期授权与隐式修改偏好

**定位**：托盘第 223–272、350–354、437–442、476–486 行。

多次 consent 共享 `_ask_event/_ask_result`，旧弹窗结果可写回新配置。`bool(None)` 导致打开并保存设置时把“尚未询问”变成“拒绝”；任意设置保存都会调用 `set_autostart()`，即使用户未改自启项，也可能重写指向其他路径的已有值。

**修复**：授权状态明确区分未知/同意/拒绝，授权绑定端点与版本。仅允许一个询问，由 Tk 主线程管理；对过期请求不应用结果，新的拒绝/撤销始终优先。设置只保存用户实际变更项；未知不能因 bool 转换消失。自启项不属于当前安装时不静默接管，先确认。

**验收**：旧弹窗返回后不能覆盖新拒绝；普通 interval 修改不改变代理授权、自启注册表值。关闭窗口、60 秒超时、正在退出均不会永久等待或遗留授权弹窗。

## 6. P2/P3 问题：逐项实施要求

### F13 原子持久化、数据目录与保存反馈（P2）

**定位**：托盘第 38–43、77–82、468–488 行；引擎第 54、75–87 行。

直接覆盖 JSON、保存错误全吞；设置显示“已保存”与实际磁盘/自启结果无关。exe 所在目录不可写时，日志初始化更可能在 UI 出现前失败。

**方案**：默认数据目录设为 `%LOCALAPPDATA%/CampusReconnect/`，便携模式必须显式且可写；首次迁移旧配置只读校验并保留旧文件，不无声移动或删除。保存使用同目录临时文件、flush/适当 fsync、原子 replace，序列化写入，失败保留旧文件；成功后才更新“已保存”提示。日志初始化可降级并给出可见错误。避免为了原子保存把旧配置凭据化或复制秘密。

**验收**：权限拒绝、磁盘写失败、JSON 截断、并发保存、迁移失败；旧配置仍有效，失败不能显示成功。

### F14 两份重连逻辑分叉（P2）

**定位**：引擎 `attempt_repair()` 第 329–374 行与托盘 `repair_once()` 第 192–221 行。

CLI 支持 `account_format=isp`、重连 Wi-Fi、指定端口；托盘缺少这些能力，也没有共享错误分类。不是证明学校现在必须用 @mobile，而是能力不一致、修复容易漏一条路径。

**方案**：抽 `RepairOptions/RepairResult` 与共享服务，CLI Namespace 转模型，托盘 Config 转模型；Browser/Proxy/UI 由上层消费结果，不混在底层认证流程。不要把 UI、args、winreg 耦合进共享函数。

**验收**：同一 fake Portal、选项与故障输入在两入口得到相同请求载荷/错误码；plain/isp、三运营商和空运营商全覆盖。

### F15 空运营商被 mobile 覆盖（P2）

**定位**：托盘第 211–212、451–454 行。

`cfg.get("yys") or "mobile"` 把合法空串变成 mobile，设置重新打开也恢复 mobile。离线执行已确认。

**方案/验收**：仅缺失键使用默认值，无效 None 按校验规则处理；空串端到端保留。可用“默认校园网”显示标签映射到空值，避免空白选项难理解。保存、重开、登录载荷都必须为 `yys=""`。

### F16 端口与 Portal 身份验证/预算（P2）

**定位**：引擎第 123–158、346–350 行。

根请求只匹配正文 `:端口/snnuportal/login.jsp`，忽略 HTTP Location/状态码；匹配不验证跳转完整 URL。任意 2xx/3xx 都算可达，不能识别无关页面。五端口串行，全部失败后又回退重复检查 8601。

**方案**：解析 Location 与已知 JS 模式，归一化并验证目标为学校 Portal；支持动态有效端口而不是仅写死历史列表。结果使用 `PortalResolution(port, source, error, evidence)`，全失败返回失败，不假装已选端口。复用已获取页面与探测结果；给整个流程设预算、各阶段检查剩余时间，读取限制响应体大小。同步 Requests 的 timeout 不等于强制总 deadline，文档不得给虚假硬上限。

**验收**：JS/302/相对地址/HTML 改版/错误页面/超时/有效新端口；解析失败不提交凭据，回退不重复同一无效请求。

### F17 Wi-Fi 解析与网络选择（P2）

**定位**：引擎第 161–205 行，两入口 SSID 检查。

`"bssid" not in low` 对整行生效，SSID 值包含 BSSID 的行会被忽略；多无线接口取第一个 SSID但可能取最后一个状态；不检查 netsh 返回码、假设冒号存在。`netsh connect name=ssid` 实际按 profile 名操作，profile 未必等于 SSID。`casefold()` 让大小写不同 SSID 被视为同一目标；SSID 也不是可信网络身份证明。

**方案**：短期按接口块解析、检查返回码、严守键名、完整 SSID 匹配；中期用 Native Wi-Fi API 提供结构化适配器状态。`ssid/profile/interface` 分开配置，连接后等待 IP/路由可用；提供多网卡/有线网的明确支持边界，不仅凭 SSID 或公网能通推断校园链路。

**验收**：中英输出、无冒号异常输出、SSID 含 BSSID、双网卡、profile 别名、大小写差异、休眠恢复/定位权限拒绝。有线支持若暂不实现，明确“不支持自动认证”，不误报。

### F18 单实例 ABI 与资源生命周期（P2）

**定位**：引擎第 407–424 行；托盘第 560–568 行。

`CreateMutexW` 未声明 argtypes/restype；ctypes 默认返回 c_int，而 HANDLE 是指针宽度。当前用对象存在性作单实例判断，实际影响依赖句柄值和平台，不能直接声称当前每次都会失效。创建失败仍继续监测，是确定的 fail-open；重复实例路径没有 CloseHandle。Python 整数引用不会自动管理 Windows HANDLE，原“避免 GC 关闭句柄”的注释不准确。

**方案**：正确声明 WinAPI ABI，保存可关闭的句柄，重复路径及时关闭；明确每用户/每 Windows 会话作用域，失败拒绝后台认证或安全降级只读。保持当前不使用 ownership 的语义，不错误增加 ReleaseMutex。一次性 CLI repair 与托盘的认证也应有共同进程级排他规则，避免“watch单实例”被 `once` 绕过。

**验收**：mock 大句柄、NULL、ERROR_ALREADY_EXISTS/ACCESS_DENIED；授权后在独立 Windows 用户/测试环境做双进程测试，退出第一实例后第二能启动。不能以杀用户现有实例来测试。

### F19 Edge 兜底泛化与假成功反馈（P2）

**定位**：引擎第 305–326 行；托盘第 241–247、314–317 行。

任何 repair False 都可能开 Edge，包括其他 Wi-Fi、没网卡、Portal 不可达、探测站点受限。每轮失败反复 Popen；`edge_fallback()` 返回 None，托盘无论找到/启动是否成功都加“已打开 Edge”。

**方案**：返回 `BrowserLaunchResult`；只在目标网络且 Portal 可用、需要人工认证/验证码时建议或按用户选择打开。对同故障周期限一次，手动按钮可再次打开；不打开其他校园/家庭网络登录页。使用受控独立 profile，说明首次创建数据目录，通知表述与实际返回一致。

**验收**：Edge 不存在、Popen 失败、其他 Wi-Fi、长时间 Portal down、反复密码错误；不重复弹窗，失败通知准确。仅用 fake launcher 验证，不真实启动浏览器。

### F20 参数验证与退出码（P2）

**定位**：引擎第 484–546 行。

`--yys` 不受限；`watch --force` 明说仅 once却被 parser接受，实际执行一次然后退出且忽略修复失败；`fix-bypass` 的 False 返回不影响退出码。isp+空运营商可能形成尾部 @；手动 port choices 与动态识别的可用范围不一致。

**方案**：`--force` 只属于 once；validate 所有组合与统一范围，空 yys 仅按明确规则处理。一次结果标准化退出码：0 成功/正常无需操作，1 运行失败，2 参数/配置错误（进一步细分前兼容脚本）。无效参数在读取凭据/联网/写注册表前失败；--dry-run 永远不 POST，报告账号可脱敏。

**验收**：CLI 参数矩阵、help、watch --force 拒绝、fix-bypass mock失败退出非0；错误参数不得产生网络/系统副作用。

### F21 启动、自启与源码/二进制混用（P2）

**定位**：`run.bat` 第 5 行，`run_tray.bat` 第 9 行；托盘第 85–116 行。

源码写 Python3.10+，脚本却只找特定 Python314 路径。`launcher_command()` 在源码模式也优先相邻 exe，可能在调试新分支时下一次登录启动旧二进制；get_autostart 只检查键存在，不核对命令。移动 exe后自启变悬空。

**方案**：源码模式使用经检测的项目 venv/当前解释器，无窗口启动前验证依赖；打包模式仅启动当前 exe，不凭文件名切换入口。自启命令对应当前安装路径，外部旧路径先确认；成功/失败明确显示，不需要管理员权限。开发环境使用明确 python 路径，避免全局装依赖。

**验收**：仅Python3.13/无Python但有exe/路径带空格中文/自定义exe文件名/相邻旧exe/移动路径/旧自启值；开发分支不会自动跑到旧exe。

### F22 测试、依赖和发布可追溯（P2）

**定位**：仓库全树；`CampusReconnect.spec` 第 1–47 行。

没有 tests、依赖文件或 CI；spec collect_all 多后端但没有锁版本。exe忽略规则本身合理，不要求把33MB附件纳入Git；问题是发布缺少可核对的源码提交、运行时/架构与构建配方。单次 log 成功不足以保证换机首跑。

**方案**：增加 `pyproject.toml` 或 requirements+锁文件（运行/开发/打包分组），明确支持 Python 与 Windows 架构。用 Windows CI 执行离线测试/静态检查/构建；Actions权限默认只读，发布仅受控tag工作流提升，第三方actions锁不可变提交。构建不注入用户凭据，不上传日志/配置；exe带版本/源commit信息，校验SHA256、大小、架构、依赖清单。安全提醒不能直接等同为安全；代码签名可选，不在本轮强求。

**验收**：全新环境按锁定清单可构建并通过测试；Release对照源码SHA与校验文件；假凭据首跑与只读目录启动用测试构建验证。重建产物的字节哈希不必然相同，不把可复现流程夸大成必然bit-for-bit复现。

### F23 实时状态和诊断上下文（P3）

**定位**：托盘第 163–189、414–488 行；引擎第 75–87、479–481 行。

设置中的Label只在打开时赋值，不是实时；tooltip没有README所说的端口。CLI异常仅类型名，--verbose没有增加实际traceback；重复setup_logging可堆叠handler。多个菜单偏好变更未显式刷新UI，不能把具体平台刷新问题当已实测故障。

**方案**：UI队列定时更新StringVar、关闭时取消回调；菜单/tooltip用统一状态快照。日志增加操作ID、阶段、结构化错误码和耗时，debug受控traceback并脱敏；不记录body、完整账号、密码、Cookie。日志初始化幂等，敏感数据用自动测试检查。

**验收**：设置开着时状态能更新，tooltip行为与文档一致；重复setup无重复日志；错误可定位但测试秘密不出现在日志。

### F24 文档边界不准确（P3）

**定位**：README 第 151、170–172、191–195、241 行；用户手册第 36–40、169、191–195、217–220、234–237 行；流程图最后“代理全程不操作”说明。

需要统一修正文案：

- “此应用无法在你的电脑上运行”**不只**代表下载损坏，还可能是架构/系统/策略兼容问题；先校验再检查架构与安全策略，不能保证不是安全或版本问题。
- “同时测两个地址”实际是顺序尝试、首个成功即返回。
- “唯一网络请求是Portal”遗漏Microsoft/Apple探测请求。正确写“不上传账号给作者/云端；存在公网连通性探测，网络服务可能看到源IP”。
- “不动系统代理”应限定CLI核心默认行为；托盘经授权可启用代理。仅写注册表不能保证所有应用/Clash UI立即同步。
- “不执行logoff”是程序可承诺行为，但“不影响其他设备”还取决于学校同账号并发策略，不能作绝对保证。
- 任务计划步骤重复，默认“最高权限”无必要；普通当前用户权限足够，删掉无必要提权建议。
- FAQ新增Q3后错误引用仍写按Q5检查密码，实际密码问题在Q6。
- 说明学校专用Portal，改SSID并不让程序自动适配其他学校。
- 区分密码保存至Windows安全凭据存储与“完全不落盘”；凭据库本身为持久化安全存储，不能用字面不落盘误导。

**验收**：每一网络目的、系统写入、支持范围和错误提示都能在代码/测试中找到依据。本文之外的原文档本次未直接修改，待实现对应功能后一并更新。

```text
campus_reconnect_tray.py     Tk/托盘入口；不拥有认证逻辑
campus_core.py              Config/Options/Result、认证服务、调度与纯解析
campus_windows.py           Wi-Fi、凭据、代理、自启、互斥体适配层
tests/                      离线测试与脱敏fixture
```

不要第一步就拆成大量层级文件；先用类型化结果和测试稳定行为，再抽模块。以上是计划，不是本次已经创建的文件。

### 7.2 核心契约

- `Config`：版本、ssid/profile/interface、operator、account_format、interval、threshold、cooldown、browser_fallback、proxy_consent/endpoint。不要包含密码。
- `ProbeResult`：结果类型、来源、HTTP状态、错误类别、耗时；不含响应正文。
- `PortalStatus`：已认证/需登录/验证码或需人工/不可达/未知结构；已登录账号仅在内部精确比较，对外脱敏。
- `RepairResult`：操作ID、网络结果、认证结果、error_code、retryable、elapsed、port、是否允许人工处理。认证/联网/代理三项结果独立。
- `CredentialStore`：安全读取/写入接口，错误类型可区分；密码从repr、日志、配置、线程事件和产物排除。
- `Scheduler`：单调时钟、failure streak、busy、next_attempt、backoff、取消/配置版本。
- `WindowsAdapters`：注入式接口，mock可替换全部注册表/凭据/浏览器/网卡/互斥操作。

### 7.3 线程与状态约束

```text
Tk主线程：窗口、授权、设置、UI状态更新
    -> 命令队列：探测/手动重连/暂停/配置变更/退出
单网络工作线程：拥有Session与认证排他性
    -> 结果队列：状态快照/错误/需要用户处理
    -> Windows副作用：只在授权、取消令牌和版本检查通过后执行
```

通知与托盘菜单按后端支持方式更新；Tk调用只能由Tk线程消费队列执行。不要为了“同时两个探测”增加共享Session线程；先保留顺序且有预算的探测。

建议状态：`STARTING / ONLINE / SUSPECT / WIFI_DISCONNECTED / NON_TARGET / AUTH_REQUIRED / REPAIRING / AUTHENTICATED_DEGRADED / NEEDS_USER / ERROR / PAUSED / STOPPING`。托盘可映射到现有颜色，但设置面板要显示细分类别。`SUSPECT`不等于认证失败，非目标网络不应通知“校园网断开”或自动打开Portal。

## 10. 本次已经得到的离线验证输出

抽取源码原函数并注入假对象得到以下结果（测试密码均为占位值，无真实网络与系统写入）：

```text
login_http500_account_substring= (True, 'Portal 确认已在线（账号出现在状态页）')
portal_http302_reachable= True
probe_arbitrary_success= (True, 'http://test.invalid')
invalid_config_survives= bad 'false' True
save_permission_failure_return= None
empty_yys_sent= 'mobile'
proxy_failure_return= False proxy_enable_after= 1
watch_attempt_times_with_180s_cooldown= [0, 30]
source_syntax=OK
```

解读：

- 登录误判由原函数直接复现，不只是猜测。
- 302被称可达只是现有宽泛语义，不能据此证明响应是正确Portal页面。
- 任意Success子串会通过探测；非法配置与授权字符串没有被拦截。
- 写配置失败不向调用者返回失败状态；空运营商确实被改成mobile。
- 假注册表模拟缺少查询权限，复现“函数失败但启用位已改变”；没有向真实注册表写入。
- 冷却绕过用自定义threshold=1暴露算法缺陷，默认threshold=3也可能在足够短的失败/恢复序列中早于180秒再试；不是断言默认30秒固定重登。
- 源码AST语法通过只说明可解析，不等于程序所有路径或Windows二进制通过。

## 11. 不应改变的边界与本轮非目标

### 必须保留

- 不主动执行Portal注销，不通过踢掉用户会话来测试恢复。
- 核心探测与登录不依赖系统代理；保留 `trust_env=False`。这不绕过TUN/路由层代理，应在文档明确。
- 凭据留在当前Windows用户的安全存储，不改成JSON、环境变量、云端或日志。
- CLI命令尽量兼容；会破坏安全边界的无效组合直接拒绝并明确迁移说明。
- 学校专用适配器与系统能力分开，未知Portal变化安全失败、停止提交秘密。
- 系统代理、自启与浏览器都是明确副作用，用户可以分别控制，不因“网络修好了”顺带接管其他软件配置。

### 本轮不做

- 不做多学校通用平台、账号云同步、自动验证码破解、门户暴力重试。
- 不引入服务器/数据库/远程遥测，仅本机运行。
- 不先更换GUI框架、不为体积优化贸然删除安全后端或禁用证书校验。
- 不自动修改Clash配置文件、订阅或TUN设置。
- 不更新现有Release附件、不挪动v0.1标签；验证通过后建议发新版本，如v0.2，而不是悄悄覆盖已公开产物。
