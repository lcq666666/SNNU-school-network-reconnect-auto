## 1. 总体目标

将当前 V0.3 从"有完整模块、离线测试通过，但真实双网卡闭环尚未验证"，
升级到"真实可用、可恢复、适合远程无人值守"的状态。

系统最终需要：

- Ethernet 正常时优先使用有线，不重复提交 SNNU Portal 认证。
- Ethernet 物理连接仍在但实际断网时，能够识别上游故障。
- SNNU Wi-Fi 可以作为独立备用路径进行健康探测、连接及认证。
- 需要时能够经过受控 Metric 调整切换默认公网出口。
- 有线恢复后进行稳定性判断，避免网络反复抖动。
- 远程会话正在进行时，避免不必要的自动切回。
- 网络操作失败后保留有效恢复信息，不能导致未知路由状态被误判为正常。
- Windows 重新启动、进程异常或网络恢复后能够按照经过验证的方式恢复监控。
- 保持 Clash Verge Rev 系统代理不被意外关闭或修改。

## 2. 必须修复的核心问题（F75-01 .. F75-08）

### F75-01 托盘缺少真实三轴健康快照

`campus_reconnect_tray.py` 的 `_failover_snapshot_provider` 缺省为 `None`，
AUTO 可能消费只有 `system_online` 的轻量快照。

修改托盘 worker，让它接入真实 `NetworkObserver` 和 `InterfaceHealthChecker`。
AUTO 只能使用完整、新鲜且可信的 Ethernet/Wi-Fi/System 快照做决策。
轻量快照只能用于显示占位，不能授权路由切换。

### F75-02 MONITOR / LOCKED 仍可能运行旧认证流程

审查 `_probe_tick()`、`_failover_owns_actions()`、`_run_repair()` 等函数，
防止 V0.2 自动重连与 V0.3 双网卡调度并行。

保证 MONITOR、LOCKED 模式下背景不自动认证、重连 Wi-Fi 或修改 Metric。
人工手动重连可以保留，但必须明确触发、确认并共用互斥机制。

### F75-03 非默认出口 Wi-Fi 无法可靠确认健康

当前部分探测依赖 `Find-NetRoute` 的系统最佳路由结果，这与验证备用网卡可用性不是一回事。

必须分别实现：

- 系统当前默认出口识别。
- 指定物理网卡的独立连通性检测。
- SNNU Portal 请求的接口约束与出口证据。
- 切换完成后的实际路由与公网复核。

研究 Windows 下可靠的接口约束连接方式，不要仅凭 `source_address` 或 `trust_env=False`
声称认证请求一定经过 SNNU。认证出口不能证明时，禁止发送真实凭据。

### F75-04 Wi-Fi 重连后使用旧 IP

修改 `_build_composite_executor()` 与 SNNU 执行器。
每次认证前重新读取接口标识、无线 IPv4、路由及最新健康状态。

Wi-Fi DHCP 地址变化后，必须废弃旧网络会话与连接池，避免使用已经失效的绑定地址。

### F75-05 路由事务日志与回滚不够安全

修改 `RouteJournal`、`RouteGuard.apply()`、`RouteGuard.rollback()` 和 `recover()`。

要求：

- 原子化日志写入。
- 损坏日志明确报错，不当作空日志。
- 回滚失败保留 pending 或 RECOVERY_REQUIRED。
- 不能仅因为修改了 Metric 就判定切换成功。
- 切换后需要验证真实公网路径。
- 切回失败时必须执行实际恢复操作，不能只改变状态机状态。
- 无可靠恢复条件时停止自动写入并告警。

### F75-06 远程敏感期判定不充分

Tailscale 可能使用 UDP。不能仅因为没有 Established TCP 就推断没有远程会话。

完善 `RemoteSafetyGuard`，结合具体远控软件的可验证会话信号。无法确认时保守处理。

当健康 Wi-Fi 正在承载远程会话时，默认不为了恢复有线优先而强制切断远控。
当前 1800 秒强制放行策略改为可配置，并优先使用等待空闲策略。

### F75-07 Windows 路由写权限

AUTO 授权不代表用户进程有管理员权限。

设计最小权限路由执行入口。普通监控和校园网认证不应以管理员权限运行。
任何受限执行器必须有物理网卡允许清单、参数校验、日志和失败反馈。

不得为了方便而直接提升整个托盘程序权限。

### F75-08 看门狗不能只检测线程是否活着

当前 `MonitorWatchdog` 需要覆盖线程存活但心跳长期不更新的情况。
完善心跳超时、可取消 I/O、有限重启、重复恢复保护。

明确进程内 watchdog 无法应对整个进程崩溃，后续需要经过测试的独立启动或恢复机制。

同时修正 DNS 全局探测与接口诊断混淆、网关 TCP 端口关闭导致误判，
以及无人值守检查中"支持睡眠"和"实际配置睡眠"混淆等问题。

## 3. 分阶段实施要求

### P7.5-0：建立基线与复现

- 同步远端，不覆盖未提交文件。
- 记录本地、远端 SHA。
- 建立详细 TODO。
- 使用 Mock 测试复现核心问题。
- 产出缺陷复现报告和每个问题的源码证据。
- 复现用例可临时加入默认排除的 regression 测试分组；单独运行记录预期失败，
  修复后必须移入正常默认回归。
- 不执行真实网络修改。

完成后提交、推送并汇报。

### P7.5-1：托盘与模式隔离

- 接入真实完整三轴快照。
- 增加结果新鲜度、超时和缓存代次检查。
- AUTO 数据不足时拒绝执行。
- 统一旧版自动重连和新版故障切换的副作用入口。
- 确保 MONITOR、LOCKED 后台没有隐形认证动作。

必须有离线单元和完整托盘调用链集成测试。

### P7.5-2：独立网络探测

- 修正非默认 Wi-Fi 出口的探测机制。
- 实现可核实的接口约束能力。
- 区分 Portal 需要认证与公网不可用。
- 修正 DNS、网关和接口出口混淆。
- 对无法证明路径的请求 fail-closed。

不能为了测试通过而把不可靠状态强行视为健康。

### P7.5-3：动态无线认证

- 每次认证重新获取 SNNU 网络信息。
- 单独建立绑定会话。
- 不复用 DHCP 变化前的源地址。
- 区分 Portal 认证成功与公网真正恢复。
- 仅在确实发生认证尝试后登记对应冷却。
- 防止多入口并发提交凭据。

继续复用 V0.2 的 `repair_service()`。

### P7.5-4：路由事务修复

- 路由快照和日志必须可靠持久化。
- 写入失败、回滚失败、崩溃恢复都必须有独立结果。
- 切换前验证目标链路，切换后使用新鲜数据复核。
- 切回验证失败必须真正恢复可用路由。
- 不允许状态机显示"Wi-Fi 已接管"，实际却仍在错误的以太网路由上。
- 增加事务并发及恢复幂等测试。

此阶段未通过，不允许进行真实 Metric 切换实验。

### P7.5-5：远控安全

- 优化 Tailscale/RDP 等远控会话判定。
- 远控状态 UNKNOWN 时按保守策略处理。
- 非紧急切回优先等待远程会话结束。
- 修复活线程卡死的看门狗判断。
- 设计可靠的无人值守启动与恢复机制。
- 读取实际电源计划，不假定系统支持睡眠就一定会自动睡眠。
- 不默认启用 Windows AutoAdminLogon。

### P7.5-6：权限、UI 与配置

- 实现受限的路由操作权限边界。
- 明确区分自动切换未授权、权限不足和网络故障。
- 保持 AUTO 默认关闭。
- Clash 默认保持原样。
- 旧配置升级不能自动授权真实路由写入。
- 完善托盘状态、告警、README 和用户手册。

### P7.5-7：完整离线集成

必须通过包含真实生产组装入口的 Mock 闭环：

- 双网络正常时有线优先。
- 有线逻辑断网但物理 Up。
- SNNU 非默认路由且需要认证。
- Wi-Fi IP 地址变化。
- Metric 修改失败与回滚失败。
- Wi-Fi 接管和稳定有线切回。
- Tailscale 活跃会话推迟切回。
- MONITOR/LOCKED 长时间运行零背景副作用。
- 线程故障与崩溃恢复。
- Clash 保持原样。

运行全部已有测试和新增测试，运行 Ruff。

输出 P7.5 验收报告，结论必须逐项对应测试和源码证据。

## 4. P8 真实环境验收

P8 只能在 P7.5 全部出口条件满足后启动，且必须获得用户明确授权。

测试顺序：

1. 双网卡同时连接及实际出口识别。
2. SNNU 备用链路可达性。
3. 有线健康时零重复认证。
4. SNNU 受控 Portal 认证。
5. Wi-Fi 地址变化。
6. 有线正常和 Wi-Fi 正常时的 Metric 基线。
7. 受控小范围真实路由切换。
8. 网线拔出自动接管。
9. 网线保持插入但上游公网故障自动接管。
10. Wi-Fi 未认证情况下的接管。
11. 两条链路同时故障。
12. 有线恢复与防抖切回。
13. Metric 回滚和异常恢复。
14. 真实远程会话下的网络故障恢复。
15. 活跃远程会话期间安全延迟切回。
16. Windows 重启、锁屏、启动和无人值守恢复。

真实测试必须有人在电脑旁，提前保存网络状态，确认本地控制台及回滚方案。

测试失败立即停止后续危险操作。

验收只有 `PASS`、`PARTIAL`、`BLOCKED` 或 `FAIL` 四种结论；
不能以离线测试代替真实远控恢复验收。
