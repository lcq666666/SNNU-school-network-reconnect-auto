# V0.10.0 安装启动失败修复验收

## 问题与处理

另一台 Windows 电脑安装更新后，启动器报 `Failed to load Python DLL`，路径指向 `%TEMP%\_MEI...\python312.dll`。Windows 加载器的“找不到指定的模块”也可能由传递依赖导致；目标电脑尚无启动日志或系统信息，不能据此确认缺少哪一个 DLL。

安装版原来也是 PyInstaller 单文件程序，启动时把 Python 和应用运行库释放到临时 `_MEI` 目录。V0.10.0 将安装版改为 PyInstaller 目录包：主程序和 `_internal` 运行库一起安装在 `%LOCALAPPDATA%\Programs\CampusReconnect`，绕过临时解压加载路径。单文件便携版继续提供。安装器限定 Windows 10/11；Windows Release 构建分别启动自检单文件版与目录版。

## 离线与本机构建验证

- 新增回归测试覆盖安装器复制目录包、Windows 10 最低版本、目录构建未启用 UPX，以及用户级 Inno Setup 路径识别。
- 全量离线回归（Python 3.12.11）：1526 项，0 失败，0 错误，1 项因平台条件跳过；pytest 退出码 0。测试进程结束另输出一次后台线程 `AttributeError`，JUnit 中无失败/错误；属于仓库既有的解释器退出期线程观察项，见 `docs/阶段A_观测预算自洽_2026-11-12.md`。
- `ruff check .` 与 `git diff --check` 通过。
- Python 3.12.11、锁定依赖下 PyInstaller 6.22.3 构建单文件与目录式 EXE，两个 `--startup-check` 均返回 `ok`。目录包包含 `python312.dll`、`vcruntime140.dll` 与 `vcruntime140_1.dll`。
- Inno Setup 6.7.3 用户级安装路径可被构建脚本发现；本机安装器编译成功，`CampusReconnectSetup.exe` 为 63,634,549 字节，SHA256 `af41a32427189fc08de95f6b26b4d12092380f663baec79191dc2b0b8a5050dd`。
- 本机便携 EXE 为 88,563,965 字节，SHA256 `aad3d91fa5652b9b4349e54681d05e2df8f580e0f3e9288dd34b007b6e3c0663`。构建清单记录版本 `0.10.0`、Python `3.12.11`。
- 远端发布构建及 Release 链接状态待补充。

## 边界

目录式安装避免从临时目录装载打包 DLL，降低临时目录策略、杀毒软件隔离和解压异常影响启动的机会，但目前不能证明目标电脑故障具体由这些因素中的哪一项造成。只有在目标电脑安装 V0.10.0 并验证启动后，才能确认该现场问题是否解决。若目录式版本仍无法启动，应收集 Windows 版本、安装目录文件清单、安全软件隔离记录和对应事件日志继续诊断。
