## 3. 默认路由与 Metric 基线

```
0.0.0.0/0 via 192.168.124.1   ifIndex=10  RouteMetric=0  InterfaceMetric=25  以太网
0.0.0.0/0 via 10.138.0.1      ifIndex=5   RouteMetric=0  InterfaceMetric=35  WLAN
（无 ::/0 默认路由；IPv6 公网不可达，Find-NetRoute 对 2606:4700:4700::1111 失败）
```

- 以太网：IPv4 192.168.124.9/24，网关 192.168.124.1，InterfaceMetric 25（自动 Enabled）。
- WLAN：IPv4 为 169.254.196.157（**APIPA**，即未取得 DHCP 租约），持有多个 IPv6 地址。
- 当前公网出口（路由表查询，未发探测包）：8.8.8.8 → 源地址 192.168.124.9，经 ifIndex=10 以太网。

**风险 R-1（陈旧默认路由）**：WLAN 断开且仅有 APIPA 地址，但路由表仍保留经 10.138.0.1 的 0.0.0.0/0（NetMgmt）。该路由来自历史 SNNU 会话，Metric 35 高于以太网故当前无害，但 P5 路由卫士必须把"默认路由对应网卡无有效 IP"纳入切换前校验，P1 的 WIFI_HEALTH 也必须能识别这种"有路由、无地址"的状态，不能因存在默认路由而判定 Wi-Fi 可用。

## 4. 双网卡并存判定（P0-T3）

结论：**undetermined（暂不能确定）**。

- 未发现阻断策略：两张物理网卡的高级属性中均无"有线上网时禁用无线"类设置（50+ 项已逐条留档于原始输出 [6] 节）；电源管理查询本机无输出（`Get-NetAdapterPowerManagement` 返回码 1 且无内容，已记录）。
- 无法实测并存：以太网 Up 但 WLAN 当前 Disconnected，"以太网在线时 WLAN 是否被系统/驱动强制断开"必须由 R-0-02 人工验证。

## 5. SNNU 关联保持（P0-T4）

- 当前 WLAN 未关联任何 SSID（`netsh wlan show interfaces`：state=disconnected，SSID/Profile 均为空）。
- 因此"以太网在线时 SNNU 能否维持关联并拿到 IP"未取得证据；列入 R-0-02：连接 SNNU 后观察 60 秒，确认关联保持与 DHCP 获取（预期获得 10.x 校园网地址而非 169.254.x）。

## 6. 计时器缺陷取证（P0-T6）

代码定位（基线 `4900ca9`）：

1. `campus_reconnect.py` `watch()` 第 803–807 行：认证失败后 `next_attempt = now + cooldown`，随后 `wait = max(interval, next_attempt - now)`，本轮探测整体睡到冷却结束；
2. `campus_reconnect_tray.py` `_probe_tick()` 第 829–832 行与 `_next_probe_time()`：修复后 `_next_attempt_at = now + cooldown`，`now < next_probe` 时直接跳过探测。

两者与各自 docstring 声称的"冷却只禁止新的认证，不禁止探测"相反。

时间戳证据（VirtualClock 离线复现，interval=15、cooldown=180、threshold=1，用例 `tests/unit/test_v03_p0_timer_forensics.py` 全绿）：

| 场景 | 证据 | 说明 |
|---|---|---|
| CLI `watch()` | 探测时刻=[0, 180, 195]；认证时刻=[0] | 冷却 180s 内零探测；若公网 t=10 恢复，发现被推迟 170s（漏 11 个探测窗口） |
| 托盘 `_probe_tick` | t=0 失败→认证；t=15 tick 跳过探测；t=180 才恢复探测 | 冷却期探测被整体推迟 |

供 P2（计时器分离）修复前后对照：修复后上述用例改写为断言"冷却期内探测不暂停"。

## 9. 对后续阶段的影响与风险

1. **R-1 陈旧 WLAN 默认路由**（§3）：P1 的 `WIFI_HEALTH` 必须按"链路→IP→网关→公网"分层判定，把"有默认路由但无有效 IP/网关不可达"归为 `NO_IP`/`GATEWAY_UNREACHABLE`，不得判 `HEALTHY`。
2. **并存判定未闭环**：P3 开始热备用前必须先完成 R-0-02；若结论为"被阻止"，按计划暂停 P3 之后并报告用户。
3. **无人值守三项缺口**（自动登录/睡眠/远控客户端选择）：属于用户环境配置项，不影响 P1 开发；P7 远程保障阶段前需闭环。
4. **IPv6 无默认路由**：P4/P5 的切换验证不得假定 IPv6 可用；方案 §4.2 的"IPv6 也要检查"在本机表现为"无需切换 IPv6"，P1 契约已如实记录。
