# 阶段 C：分级执行器（DEGRADED 白名单）

日期：2026-11-12
分支：`fix/observer-degraded-20261112`
基线：阶段 B 提交 `514dc8f`（观测三态 + LKG 数据基础）

阶段定位：**真正解除「长断连自锁」**。阶段 B 已给出「是否可有限降级」的判定，
但 `NetworkFailoverManager.tick` 在 `trusted=False` 时**根本不调用 `_decide()`**，
动作计划恒为空 —— 仅替换执行器无法解除自锁。阶段 C 在用户确认的三条边界内，
第一次放宽 fail-closed 语义：DEGRADED 时把 LKG（last-known-good 快照，年龄
≤ 90s）作为**只读上下文**喂给状态机，动作仍只经单一副作用门的白名单执行器。

---

## 1. 根因回顾（为什么 A/B 还不够）

```
TrayApp._failover_tick → bridge.set_snapshot_trust(False) → RefusingExecutor
                        → bridge.tick → manager.tick(trusted=False)
                        → 「等待可信网络快照：保持当前恢复状态」   ← _decide 不执行
                        → plan == []                              ← 零动作计划
```

15:50 / 16:20 两次 10 分钟断连中 `SNAPSHOT_UNTRUSTED` 171 次、`BOTH_OFFLINE`
92 次，全程 Portal POST / Wi-Fi 重连一次都没发生。

## 2. 关键选择（用户 2026-11-12 确认）

| 项 | 选择 | 依据 |
| --- | --- | --- |
| DEGRADED 决策依据 | **允许 90s 有界窗口** | LKG 年龄 ≤ `max_age(30) + grace(60)` 时作为只读上下文喂给状态机；动作由白名单执行器兜底。这是阶段 A/B 文档约定、且唯一能真正恢复 Portal/Wi-Fi 重连的路径 |
| 白名单范围 | **Portal 认证 + Wi-Fi 重连** | 仅放行 `PORTAL_POST` / `WIFI_RECONNECT`；两者恰是「用来把网络修好」的动作，且本来就不在 `VerifiedActionGate` 的验证前置门内。`METRIC_WRITE` / `CLASH_TOUCH` / UU 重启无论何时都拒绝 |
| 限次与冷却 | **每 epoch 2 次 / 全局 180s** | 与阶段 A 文档「每 epoch 限次 + ≥180s 冷却」一致；因 180s > 90s 降级窗口，实际每个降级窗口最多执行 1 次白名单动作 |

## 3. 实现设计

### 3.1 `GradedExecutor`（`campus_tray_observer.py`）

包住真实执行器（`delegate`），协议与 `NetworkOpScheduler._invoke()` 完全一致
（`OpOutcome` / `True|None` / `False` / `str` / 异常兜底）：

* **门禁顺序**：白名单（按 `OpKind.value` 字符串比较，避免模块级循环依赖）→
  有真实执行层 → `grace_left > 0` → epoch 名额 → 冷却；
* **拒绝语义沿用 P7.5-1A**：`gate_passed=True`、`attempted=False`、
  `executed=False` —— 不消耗状态机的认证 / 重连 / 切换冷却，不谎报状态迁移；
* **参数钳位**：`check_graded_budget()` 固化「限次 1..10 整数、冷却
  ∈ [180, 3600]s」三条不变量，构造期即拒绝非法预算；
* **零时钟依赖**：`grace_left` / `epoch` / `now` 全部由调用方每轮
  `update()` 注入，可被虚拟时钟精确测试；冷却用 `max(0, now - last)`，
  时钟倒退不会绕过冷却；
* **审计台账**：`allowed`（放行的 `(epoch, kind, now, outcome)`）与
  `refused`（被拒的 `(kind, 理由)`）。

### 3.2 桥接层接线（`campus_tray_failover.py`）

* `set_snapshot_trust()` 新增**可选**关键字 `mode` / `grace_left` / `epoch` /
  `now`。**不传 `mode` 时行为与 P7.5-1 完全一致**（阶段 A/B 全部既有调用与
  1334 例零变化）——这是阶段 C 的向后兼容锚点；
* `mode=DEGRADED` 且 `trusted=False` 且窗口可用 → 接入 `GradedExecutor`
  （复用同一实例：epoch 计数与冷却台账跨轮保留）；否则立即退化回
  `RefusingExecutor`；
* `DEGRADED` 与 `trusted=True` 矛盾、`mode` 非法取值 → 一律按更严格一侧
  处理（`REFUSED`）；
* 新增 `graded_active` 属性；`tick()` 据此决定是否允许 `_decide()`：
  `decide = snapshot_trust is not False or graded_active`。冷却 / 限次用尽 /
  宽限耗尽都会使窗口关闭 ⇒ 状态机重新冻结；
* `status()` 新增 `observation_mode` / `graded_actions_left` 字段与三段式
  告警（有界降级可用 / 冷却限次中 / 窗口已耗尽），保留「不可信」关键字。

### 3.3 托盘接线（`campus_reconnect_tray.py`）

* `_full_snapshot()` 改为返回 `observation.usable_snapshot`：FULL → 本轮
  快照，DEGRADED → LKG，REFUSED → `None`（轻量占位快照不变）；
* `_failover_tick()` 把 `ObservationResult.mode` 显式传给桥接；DEGRADED 还须
  同时满足：`graded_recovery_enabled` 配置开关（缺省开启，可一键关闭）、
  LKG 通过 `is_auto_executable_snapshot()`（可定位目标接口）、宽限未耗尽；
* `epoch` 取自整合层 `dual_path.network_epoch`（接口 / 配置变化即换代）；
* **整合层与时间线仍收到 `trusted=False`**：不安排验证、不切换、不重启 UU；
  时间线 `detail` 附带「观测模式 DEGRADED（LKG 剩余宽限 Ns）」；
* 外部注入提供者（P7.5-1 兼容路径）不进入 DEGRADED：完整快照仍按结构判定走
  FULL，零行为变化。

## 4. 安全契约（本阶段最重要的不变式）

1. **缺省路径零变化**：不传 `mode` 的 `set_snapshot_trust(False, ...)` 仍是
   `RefusingExecutor`；`trusted=True` 仍是真实执行器；
2. **白名单之外零副作用**：`METRIC_WRITE` / `CLASH_TOUCH` 恒
   `attempted=False / executed=False`；`VerifiedActionGate` 的验证前置门仍在
   分级执行器**之前**（双保险）；
3. **UU 重启恒拒绝**：整合层收到 `trusted=False`，`schedules_uu_restart` 恒
   `False`；
4. **拒绝不消耗冷却**：白名单拒绝沿用 P7.5-1A 语义，状态机不会因「虚假冷却」
   被卡住；
5. **有界**：90s 宽限 + 180s 冷却 + 每 epoch 2 次 ⇒ 一次断连期间最多一次
   白名单动作；宽限耗尽 / 配置关闭 / 非 AUTO 授权立即退回严格 fail-closed；
6. **LKG 只是只读上下文**：`observation.trusted` 仍为 `False`，LKG 不进入
   `snapshot` 字段，不用于 `is_auto_executable_snapshot` 之外的任何「可信」
   判定。

## 7. 残余风险与后续阶段

1. **LKG 决策的固有滞后**：DEGRADED 期间状态机基于 ≤90s 前的接口状态推进；
   若网络身份在窗口内突变，LKG 会被签名校验立即作废（阶段 B 已保证），但
   「链路状态突变」仍可能让白名单动作打在旧状态上 —— 由 180s 冷却 + 每
   epoch 2 次兜底，最多浪费一次重连/认证尝试；
2. **`wifi_reconnect` 会真实断开 WLAN**：若 LKG 显示 LINK_DOWN/NO_IP 但实际
   已恢复，一次多余重连由 60s 重连冷却自然恢复；
3. **阶段 D**：IP + 域名双通道探测，把 DNS 抖动判为 `DNS_DEGRADED` 而非
   `NETWORK_DOWN`（日志「直连不通但代理通：结论矛盾」）；
4. **方案 B（可选）**：压缩 P1 探测开销，消除 54s 最坏采集预算；
5. **仍需重新打包**：运行中的 `CampusReconnect.exe` 是 v0.6.10，源码改动需
   release 工作流构建并做 SHA256 校验才生效；
6. 真机 / Portal / 路由 / UU kill 验收一律单独授权后执行。
