## 0. 总体规则

### 0.1 分阶段原则

1. **每阶段独立验收**：每个阶段有且仅有一份出口条件清单（Exit Criteria），全部满足才允许进入下一阶段；未满足时停留在本阶段修复，不得"带病推进"。
2. **副作用逐级解锁**：从"只读诊断"开始，到"写入系统路由"结束；越早的阶段越不允许触碰真实网络状态。阶段顺序即风险递增顺序。
3. **测试先行**：每阶段先写失败测试（含假件），再写实现；禁止无测试的合并。
4. **认证引擎不动**：V0.2 的 `campus_core.repair_service` 认证能力只允许被封装调用，不允许在派生的调度逻辑中重写或复制。
5. **V0.2 保持可安装**：在 P8 之前，V0.2 版本及其安装方式始终保留，V0.3 以独立分支/版本共存，不覆盖稳定版。

### 0.2 阶段总览

| 阶段 | 名称 | 核心目标 | 是否允许真实副作用 | 前置依赖 |
|---|---|---|---|---|
| P0 | 诊断与基线确认 | 摸清两张网卡与路由现状，确认双网卡并存可行性 | 否（纯只读） | 无 |
| P1 | 网络观察层与独立健康检测 | 新增 `campus_network.py`，实现三轴健康检测 | 否（离线 Mock） | P0 |
| P2 | 计时器分离与 V0.2 冷却修复 | 网络检测 / 认证冷却 / 切换冷却三表分离 | 中（本机可提前验证） | 无（可与 P1 并行） |
| P3 | 故障切换状态机与只读监测 | 新增 `campus_failover.py`，11 状态机与"只读监测"模式 | 否（离线 Mock） | P1、P2 |
| P4 | SNNU 备用链路与接口绑定认证 | Wi-Fi 关联、Portal 识别、按网卡绑定认证 | 是（受控、前台上人） | P3 |
| P5 | 受控路由切换与路由卫士 | 新增 `campus_route_guard.py`，快照/切换/验证/回滚 | 是（受控、单人值守） | P4 |
| P6 | 托盘三模式与手动锁定 | 智能自动 / 仅监测 / 手动锁定 | 否（离线 Mock + 界面走查） | P3 |
| P7 | 远程保障与远程重连验证 | 远控探测、敏感期延迟切回、崩溃恢复 | 是（受控、真实远控会话） | P5 |
| P8 | 全量受控验收与 V0.3 发布 | 16 项验收矩阵 + 发布条件核验 | 是（受控全量） | P6、P7 |

阶段与原方案 P0–P5 的映射：P0→P0；P1+P2→P1；P3+P4→P2；P5→P3；P6+P7→P4；P8→P5。

### 0.3 测试分级定义（全阶段通用）

| 级别 | 代号 | 执行环境 | 判定规则 |
|---|---|---|---|
| 单元 / 离线 Mock | `U-<阶段>-<编号>` | pytest + `tests/fakes.py` 假件，无真实网卡、无真实 Portal、无真实凭据、无真实 sleep（用 `VirtualClock`） | 必须全绿才可进入受控测试 |
| 离线集成 / 闭合回路 | `I-<阶段>-<编号>` | 多模块以假件串联，模拟完整故障剧本（拔线/Portal 未认证/双断/恢复），断言系统状态序列与副作用清单 | 必须全绿；任何真实副作用调用出现即失败 |
| 受控真机 | `R-<阶段>-<编号>` | 本机前台执行，人工逐步确认；执行前保存当前网络快照，执行后核对 | 全部通过 + 人工签字（记录在验收报告） |

默认测试集合沿用现有约定（`pytest -m "not regression"`）；回归缺陷用例继续使用 `regression` 标记。新测试文件统一命名 `tests/unit/test_v03_<阶段>_<主题>.py`，假件扩展统一放入 `tests/fakes.py`（新增假件见各阶段"测试基建"条目）。

### 0.4 单一副作用门（所有阶段有效）

全系统只允许 **一个** 副作用执行点（`NetworkOpScheduler`）：Wi-Fi 重连、Portal POST、Metric 写入、Clash 触碰四类动作互斥串行；任何一轮检测不允许同时触发两类以上动作。该规则从 P3 起有对应的 `U-3-*` 测试永久看守。

## 1. P0 — 诊断与基线确认（只读，零副作用）

### 1.1 目标

在不改变任何网络状态的前提下，输出一份《双网卡与路由基线报告》，确认：本机物理网卡清单、当前真实路由与 Metric、Windows 是否允许有线/无线同时连接、SNNU 关联保持能力、远控所需路径。

### 1.2 前置条件

- 位于基线分支 `fix/reconnect-stability-20261013`，V0.2 现有测试全绿（`pytest -m "not regression"` 通过）。
- 本机当前网络状态已知（若正在远程会话，先由用户确认可继续）。

### 1.3 任务分解

| 编号 | 任务 | 涉及文件 | 完成定义 |
|---|---|---|---|
| P0-T1 | 编写只读诊断脚本（不入驻、不常驻）：枚举网卡、IP、网关、路由、Metric、Wi-Fi SSID/Profile | 新增 `tools/netdiag.py`（或 `campus_reconnect.py diag` 子命令） | 一条命令输出完整报告 |
| P0-T2 | 确认两张物理网卡稳定标识（实例 GUID/PCI 地址），建立 `adapters.json` 配置草案 | `tools/netdiag.py` 输出 + 配置草案 | 标识不依赖显示名 |
| P0-T3 | 双网卡并存能力验证：以太网在线时观察 WLAN 是否被系统强制断开（读 Connection Manager 策略 + 驱动开关 + 实观测） | 诊断报告章节 | 给出"允许并存 / 被策略阻止"明确结论 |
| P0-T4 | SNNU 关联保持验证：以太网在线时 SNNU 能否维持关联并拿到 IP | 诊断报告章节 | 记录可/不可及原因 |
| P0-T5 | 远控路径确认：记录当前远控客户端、其进程/端口/出网路径，以及无人值守相关系统设置（睡眠、自动登录） | 诊断报告章节 | 清单完整 |
| P0-T6 | 现有计时器缺陷取证：阅读 `campus_reconnect.py watch()` 与托盘 `_next_probe_time()`，用日志证实"认证冷却期公网探测被暂停" | 取证记录 | 有时间戳证据，供 P2 验收对照 |
| P0-T7 | 输出《阶段 0 诊断报告》 | `docs/阶段0诊断报告_2026-10-14.md`（沿用既有阶段报告命名） | 报告含原始终端输出 |

### 1.4 独立验收标准（出口条件）

1. P0-T1 命令在本机只读执行成功，未产生任何注册表写入、Metric 变更、Wi-Fi 重连或 Portal 请求（用 `git status` + 操作前/后路由快照比对证明）。
2. 报告明确回答：两张物理网卡各是什么；当前 IPv4/IPv6 默认路由与 Metric 原值；**本机是否允许以太网与 SNNU 同时连接**（这是后续热备用设计的前提，结论为"不允许"时先暂停 P3 之后并向用户报告）。
3. 计时器缺陷取证材料完整，可作为 P2 修复前后对照基线。
4. `adapters.json` 草案中的网卡标识在重启 Wi-Fi/插拔网线后仍可复现。

### 1.5 单元测试（U-0-*）

| 用例 | 构造输入 | 预期 |
|---|---|---|
| U-0-01 物理网卡枚举 | 假 `Get-NetAdapter` 输出（含以太网、Wi-Fi、Clash TAP、Hyper-V、WSL、VPN） | 只保留物理网卡；虚拟网卡被排除但保留在诊断输出 |
| U-0-02 接口 Metric 解析 | 假 `Get-NetIPInterface`（IPv4/IPv6、InterfaceMetric、AutomaticMetric） | 字段全部正确解析，IPv4/IPv6 不混淆 |
| U-0-03 默认路由读取 | 假 `Get-NetRoute`（含 0.0.0.0/0 与 ::/0 多条） | 输出每条默认路由的 ifIndex、RouteMetric、NextHop |
| U-0-04 双网卡并存判定 | 假注册表 + 假 wlan 报表：策略允许/禁止两种 | 输出"允许/被阻止 + 依据"两种结论分支 |
| U-0-05 当前出口识别 | 假路由表 + 假 `Find-NetRoute` 结果 | 指出当前公网出口 ifIndex 与来源依据 |
| U-0-06 无 Wi-Fi 网卡边缘 | 只有以太网的输入 | 报告明确"无 Wi-Fi 适配器"，不抛异常 |
| U-0-07 多以太网边缘 | 两张有线网卡 | 全部列出并标注各自 Metric，不臆断首选 |

### 1.6 离线集成测试（I-0-*）

- I-0-01：将全部假输入跑一遍完整诊断管道，断言**零写入调用**（假注册表/假 API 调用记录里无任何写操作）。
- I-0-02：诊断输出可被机器解析（JSON），字段覆盖 P1 所需全部输入（为 P1 接口契约冻结）。

### 1.7 受控真机测试（R-0-*）

- R-0-01：本机前台执行诊断，人工比对 P0-T1 报告与 `route print`、`netsh wlan show interfaces`、网络连接属性实际值。
- R-0-02：以太网在线状态下观察 60 秒 SNNU 关联状态；插拔网线各一次，确认关联策略结论稳定。
- R-0-03：路由快照比对（操作前后）确认只读性。

### 1.8 交付物与风险

- 交付物：诊断脚本、`adapters.json` 草案、`docs/阶段0诊断报告_2026-10-14.md`、I-0/U-0 全绿测试。
- 风险与回滚：本阶段无写入，风险仅限"误跑写命令"。缓解：诊断命令只使用只读 cmdlet，代码评审逐行核对；误操作回滚 = 从基线重新导出快照。
