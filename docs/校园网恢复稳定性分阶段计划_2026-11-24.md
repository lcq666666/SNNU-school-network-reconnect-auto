## 验收场景

1. Windows 公网。模拟 TUN 正常但物理接口探测异常，以及备用网卡能上网但 Windows 当前出口未确认。网络检测未知后重新确认连续失败，UU 掉线时间独立计算。
2. 校园认证。模拟 Portal 路由走目标 WLAN、走其他网卡，以及公网走 TUN。会话重建前仍要求两轮失败和本机身份核对。只有明确收到设备已达上限的回复，才暂停自动登录 15 分钟。恢复过程中断后，后续的绑定认证可补完登录，原下线冷却继续有效。
3. UU 和守护。模拟后来安装 UU、部分用户态进程已退出、补启动未出现新进程。守护任务用当前用户的交互式登录注册并回查。恢复卡死助手前，同时确认心跳、进程创建时间与可执行文件路径。
4. 系统影响。常规校园认证使用绑定的直连请求。已留下的代理备份继续支持回滚。整机自动重启须启用，应用内等待至少 60 秒后读取新鲜公网结果和 Windows 锁屏状态。
5. 验证码页面。验证码输入框、图片和隐藏字段从同一个表单读取。模拟不相关表单、表单不明确、图片识别失败和 Portal 拒绝等情况。

## 待真机验收

- 开着 TUN，开机后遇到 Portal 显示在线但实际没网。检查自动重登、实际公网恢复和 UU 控制端连接。
- 验证 Windows 任务注册成功、重新登录后运行、助手异常退出后被拉起。用模拟测试覆盖了任务参数和流程，任务权限仍需在目标机验证。
- 使用真实 Portal 回应确认设备满额提示、验证码页面结构和恢复行为。五台设备的容量由 Portal 管理。有线作为备用维护前提时，仍需确认有线确实在承载公网流量，无法确认时继续观察。
