# V0.6.9 跨电脑代理兼容计划

目标：将本机手动配置的校园网绕过能力做成可分发功能。Windows 10/11 x64；不假定代理端口、用户名、安装路径，不把没有验证的 TUN 配置显示为已生效。

## 阶段与 TODO

- [x] P0：核实现有直连请求、系统代理事务与设置入口，确定兼容范围。
- [x] P1：只读检查、系统绕过事务、Clash Verge Rev 持久脚本和 TUN 规则、备份恢复、首次运行提示及离线回归完成。32 项新增兼容用例通过。
- [ ] P2（进行中）：全量离线测试与 ruff 已通过；继续打包启动自检、推送工作分支、发布 v0.6.9 并核对产物。

## 实施约束

首次启动只读检查并提示，不在未确认时修改用户代理。设置入口提供明确范围的一键修复、撤销和规则导出。已有恢复流程沿用每台机器自己的代理快照。系统绕过只追加校园地址，不更改代理地址、端口、开关或 PAC URL。PAC 脚本不由助手改写，明确提示其兼容限制。

对已识别 Clash Verge Rev 配置，在用户关闭客户端后备份并修改持久绕过与全局脚本，避免运行中的客户端覆盖配置。不修改订阅、不停止代理/TUN进程、不更改代理模式。对其他客户端导出标准 Mihomo/Clash 规则及说明，由用户合并到客户端的持久覆写。TUN 使用门户 IP 的 route-exclude-address 与域名的 fake-ip-filter，并将 DIRECT 规则前置；全局模式不宣称规则分流生效。检查当前生成配置可以识别客户端其他脚本/GUI 覆写后规则不完整的情况。

为避免旧逻辑影响跨电脑使用，同步修复旧双轴自愈的固定端口回退与真实执行：只使用明确的本机端点，未同意联动时不执行；临时切换采用持久快照与 finally 原值恢复；移除按默认路径停止/拉起 Clash 的行为。

发生配置冲突或备份失败时停止修改；恢复时检测用户的后续改动，拒绝直接覆盖。诊断信息不展示控制器密钥、订阅地址、账户密码或 Cookie。

## 验收标准

- 无代理、不同端口、PAC、Verge 自定义/默认绕过、多客户端、缺失/损坏 YAML、TUN 与全局模式均有确定结果。
- 保留用户绕过规则、分流规则与 DNS/TUN 设置；重复应用不重复添加。
- 写入失败回滚、并发改动拒绝覆盖、备份恢复均有离线用例；测试不触碰本机真实注册表与代理文件。
- 新版 EXE 启动自检覆盖 YAML 依赖与规则生成；完整离线集与 ruff 通过后发布。
- 本机实际联网恢复和其他客户端实际导入验收单独记录，不能以规则生成测试替代。
