# V0.7.1 阶段 D：IP + 域名双通道校验分类（DNS_DEGRADED）

日期：2026-11-12
分支：`fix/observer-degraded-20261112`（基于阶段 C 推送 HEAD `e3109c67f2d177eb6dc1720f0057cb4fea651558`）

## 1. 问题与根因

2026-11-12 16:29:58 真实事件：连接后校验（`verify_internet`）全部走**域名探测**
（闸门 baidu + 交叉 qq/163/sohu），本机 DNS 降级时四站全败，被定性为
「疑似假死」；同一时刻 Clash 双轴却报「直连不通但代理通：结论矛盾」——

- 直连轴：域名探测 → 本机 DNS 失败 → `direct_ok=False`；
- 代理轴：域名由**代理远端**解析 → 不受本机 DNS 影响 → `proxy_ok=True`；
- 于是出现矛盾结论，而实际上整网（IP 层）是通的。

关键事实：`internet_ok()` 早已内置**免 DNS 的 IP 级 TCP 通道**
（`DEFAULT_TCP_TARGETS = 223.5.5.5:443 / 120.53.53.53:443`，IPv4 字面量、
K-6 实机验证可达），能正确区分「整网离线」与「仅域名解析失败」。
阶段 D 把这一判据接入连接后校验与 Clash 双轴证据链。

## 2. 用户确认的安全边界（2026-11-12 AskUserQuestion）

| 问题 | 结论 |
| --- | --- |
| DNS_DEGRADED 的 IP 通道判据用什么？ | **复用既有 IP 级 TCP 双点**（`DEFAULT_TCP_TARGETS`），不新增探测目标 |
| DNS_DEGRADED 的动作语义边界？ | **只改分类与告警**：不改变任何门禁 / 状态机 / 重认证 / 路由 / UU 行为 |
| Clash 双轴「直连不通但代理通」矛盾结论如何处理？ | **verdict 保持 unknown 不变，只补证据日志**，不做任何自动操作 |

## 3. 实现设计

### 3.1 引擎层（campus_reconnect.py）

- 三态常量：`VERIFY_OK="OK"` / `VERIFY_DNS_DEGRADED="DNS_DEGRADED"` /
  `VERIFY_OFFLINE="OFFLINE"`，`VERIFY_VERDICTS` 元组契约。
- `ip_channel_ok(*, tcp_probe=None, targets=None, timeout=None)`：
  复用模块级 `IP_TCP_PROBE` / `DEFAULT_TCP_TARGETS` / `IP_PROBE_TIMEOUT`；
  任一目标 TCP 握手成功即视为可用；探测异常只算该点不可达，绝不向上抛。
- `verify_internet_classified(session, *, tcp_probe=None)`：`verify_internet`
  的只读包装——域名通过 → `(True, OK, 域名明细)`；域名失败 + IP 通道可达 →
  `(False, DNS_DEGRADED, 域名明细 + IP 证据)`；两路都失败 →
  `(False, OFFLINE, 域名明细)`。
- **`verify_internet` 本体逐字不动**：`(ok, detail)` 契约、CLI watch 路径
  全部保持原状。

### 3.2 托盘层（campus_reconnect_tray.py）

- 导入 `ip_channel_ok`、`VERIFY_DNS_DEGRADED` 进托盘命名空间（可打桩）。
- `_verify_online_async._run`：域名校验失败后先经 IP 通道复核——
  - IP 通道可达 → 日志「连接后上网校验未通过：DNS_DEGRADED（IP 通道可达，非假死）」
    + 气泡「（DNS_DEGRADED，非假死）」；
  - IP 通道不可达 → **旧「疑似假死」文案逐字保留**；
  - 校验通过 / 异常分支完全不变；`_start_clash_check_async(ok)` 触发点不变。
- `_dual_axis_clash_check`：当 `verdict == unknown` 且直连轴失败、代理轴成功、
  且 `ip_channel_ok()` 为真时，追加证据日志「直连轴域名失败但 IP 通道可达
  （免 DNS），疑似本机 DNS 降级——代理轴域名由代理远端解析，故代理通」；
  IP 复核异常只算不可达；verdict 与自愈行为完全不变。

### 3.3 测试封闭性

既有两个失败校验托盘测试（`test_v04_tray_verify.py` /
`test_v04_tray_remote_restart.py`）补 `tray.ip_channel_ok → False` 打桩，
保持旧 OFFLINE 分支语义、不依赖真实网络。

## 4. 安全不变量

1. 分类结果**只**进日志与气泡，不进入任何判定/门禁/状态机输入。
2. `verify_internet` 契约逐字不变；CLI 与引擎内部调用方零感知。
3. IP 通道探测目标与 `internet_ok()` 完全同源（双 IPv4 字面量），零新增外部依赖。
4. 所有新增探测异常均被吞掉并降级为「该通道不可达」，绝不抛出到校验线程之外。
5. Clash 双轴 verdict 语义逐字不变；证据日志只在矛盾分支追加。
6. 校验线程仍为独立短命线程，异常边界（V0.4）保持不变。
