## 5. 环境变更（经用户确认）

- **背景**：阶段 0 的 `.venv` 基于托管 Python 3.13.14，该解释器**不含 tkinter**
  （无 `_tkinter.pyd`、无 `Lib/tkinter`、无 `tcl/`），导致托盘模块 `campus_reconnect_tray.py`
  无法导入，依赖它的回归用例无法收集。
- **决策**：经用户确认，**用本机 python.org Python 3.13.7 重建 `.venv`**（含 tkinter 8.6），
  保持 Python 3.13 与既有命令路径 `.venv/Scripts/python.exe` 不变。
- **重建命令**：
  ```bash
  "C:/Users/Asus/AppData/Local/Programs/Python/Python313/python.exe" -m venv --clear .venv
  .venv/Scripts/python.exe -m pip install -r requirements-dev.txt
  ```
- **核验**：`sys.version=3.13.7`、`tkinter.TkVersion=8.6`、`sys.prefix` 指向项目 `.venv`；
  `requests/keyring/pystray/PIL/pytest/pytest-cov` 均可导入；未污染全局环境。

## 6. 与计划的偏差与说明

1. **默认集合与回归集合分离**：计划允许回归用例「暂存于单独未启用集合」。
   本阶段用 `regression` 标记 + `pytest.ini` 的 `addopts = -m "not regression"` 实现：
   默认 `pytest` 全绿（满足 AGENTS §1.4「全部既有测试必须通过」），
   `pytest -m regression` 单独展示「修复前失败」。修复对应缺陷后移除标记即并入默认集合。
2. **T05 的「JSON null/list/截断」子项**：现有 `load_config()` 已由 `try/except` 安全回退，
   **不是可复现缺陷**，故不作为失败回归项，其基线固化在
   `tests/unit/test_tray_config_baseline.py`；T05 的失败回归项取「未知键未隔离」。
   验证器对 malformed JSON 的完整覆盖在 `tests/unit/test_campus_core_config.py`。
