# V0.9.8 长时间断联误判修复

## 现场依据

- 本机原安装版为 v0.8.2；日志从 09:26:23 到 12:59:15 持续记录重连，期间反复出现“Portal 已在线但公网探测仍未通过”。
- 直接连接 SNNU Wi-Fi 时，校园状态页确认 Portal 为 ONLINE，百度闸门通过；QQ 返回 HTTP 501，163 与搜狐返回 HTTP 403。
- 同一 Wi-Fi 接口绑定、绕过代理后，项目既有的 Firefox、Apple、Microsoft NCSI 检测点均严格匹配通过。这将故障定位为验证目标不一致/目标站响应限制，不能证明账户超设备数限制，也不能单凭它排除历史故障期间的上游波动。

## 修改

- 保留百度 HTML 标题闸门与“至少两个独立交叉点”的恢复判据。
- `VERIFY_CROSS` 复用 `campus_network.DEFAULT_HTTP_TARGETS`，确保状态监测、备用链路和恢复协调器使用同一组已验证站点。
- 新增离线回归：三个站点中一个返回 501 时，百度闸门和另外两个独立探测点通过即可判定公网可用。
- 没有加入无线注销或额外强制重新登录行为，不会因此踢掉另一台设备。

## 验收

- 定向恢复测试：`test_v04_verify_internet.py`、`test_v05_path_verification.py`、`test_v05_dual_path_integration.py` 全部通过。
- 全量回归：`.venv/Scripts/python.exe -c "import gc; gc.disable(); import pytest, sys; sys.exit(pytest.main(['-q','-ra']))"` 通过；1 项因平台条件跳过，零失败。
- 静态检查与补丁检查：`ruff check .`、`git diff --check` 通过。
- 实机接口绑定验证：WLAN ifIndex 12 / `10.138.106.199`，百度闸门与 Mozilla、Apple、Microsoft 三个交叉点均通过，Portal 为 ONLINE；探测绕过系统代理且绑定实际 WLAN 接口。
- GitHub Windows v0.9.8 发布构建成功，Actions run `43704235900`；本机最终通过后续 v0.9.9 更新器验证并运行 v0.9.9。

## 边界

探测修正不能克服校园账户并发设备数限制、上游整体故障、Portal 服务故障或 UU 服务器故障。若仍复现长时间断联，应依据 v0.9.8 逐站日志判断 Portal、DNS、网关、出口或 UU 外连哪一层失败。
