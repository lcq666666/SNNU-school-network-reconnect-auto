## 1. 为什么需要阶段 B

但 2026-11-12 的日志显示，真实断网时 `netdiag` 是**直接抛错**而不是慢：

```

```

失败时不发布新快照，`_snapshot` 仍是旧数据；30 s（`max_age`）后判 `STALE`，
`RefusingExecutor` 接管单一副作用门，Portal 认证 / Wi-Fi 重连 / Metric 写入
全部被拒 ⇒ **零副作用自锁**，直到外部条件偶然恢复（15:50 断 10 分 00 秒、
16:20 断 9 分 55 秒）。当日 `SNAPSHOT_UNTRUSTED` 171 次、`BOTH_OFFLINE` 92 次。

阶段 A 文档 §6 已把这一半根因明确留给阶段 B/C；本阶段完成其中的**观测层**。

## 2. 关键选择（用户 2026-11-12 确认）

| 项 | 选择 | 依据 |
| --- | --- | --- |
| 有界宽限 | **60 s** | 总窗口 `30 + 60 = 90 s`，覆盖一次跑满 `collect_timeout=45` 的病态采集 + 一次重采间隔（48 s）并留抖动余量；对应阶段 A 文档 §7「45–60 s 进入有限宽限」上限 |
| `trusted` 语义 | **保持不变** | 阶段 B 只加分级数据模型，`DEGRADED` 仍 `trusted=False`、仍零副作用；阶段 C 才接白名单。既有 1287 例零回归 |

宽限另设硬上限 `MAX_DEGRADED_GRACE = 300 s`，且构造期即钳位，防止把「有界」
配成事实上的永久宽限。纯函数 `check_degraded_window()` 固化三条不变量：
宽限为有限正数、不超过硬上限、`max_age + grace >= collect_timeout + min_interval`。

## 3. 三个观测模式

| 模式 | `trusted` | 含义 | `usable_snapshot` |
| --- | --- | --- | --- |
| `FULL` | `True` | 本轮快照可信（阶段 A 语义完全不变） | 本轮快照 |
| `DEGRADED` | **`False`** | 本轮采集/新鲜度异常，但有可用 LKG 且宽限未耗尽 | LKG 快照 |
| `REFUSED` | `False` | 严格 fail-closed | `None` |

`ObservationResult` 新增字段（全部带默认值，既有关键字构造零改动）：
`mode`、`stale_for`、`grace_left`、`lkg_snapshot`；新增 `is_degraded` 与
`usable_snapshot` 属性，`to_dict()` 增加 `mode / stale_for / grace_left / has_lkg`，
`format_observation()` 增加模式行与剩余宽限。`CONTRACT_VERSION` 升为
`v03-p75-obs-2`。`mode` 缺省时由 `__post_init__` 按 `trusted` 推导，保证
`ObservationResult(trusted=True)` 仍是 `FULL`、`ObservationResult()` 仍是 `REFUSED`。

## 4. last-known-good（LKG）的定义与生命周期

LKG **不是**「任意发布过的快照」，而是「最近一次**结构完整且可定位目标接口**、
曾经能授权 AUTO 执行」的快照：记录时同时通过 `is_full_snapshot()` 与
`is_auto_executable_snapshot()`，与 AUTO 授权使用同一套真值。

- 只由采集线程 `_run()` 写入，`observe()` 纯读（保持「永不阻塞、永不 I/O」）；
- 记录 `lkg_at`（发布时刻）、`lkg_external`（**外部**配置代次）、`lkg_signature`
  （接口身份）；
- `invalidate()`（配置 / SSID / 模式变化）与网络身份变化（DHCP / 出口接口变化）
  立即清空 LKG；
- **内部任务代次因采集超时自增不清空 LKG** —— 那只是任务失败，网络身份没变；
  若一并作废，恰好会在最需要降级的时候退回 `REFUSED`。

## 5. 进入 `DEGRADED` 的全部条件（任一不满足即 `REFUSED`）

1. 本轮结论属于**软失败**：`STALE / COLLECT_ERROR / COLLECT_TIMEOUT / COLLECTING`；
   或 `GENERATION_MISMATCH` 但确认「外部配置代次与接口签名均未变」（超时自增）；
2. 存在 LKG，且结构完整、可定位目标接口；
3. LKG 的外部配置代次与接口签名均与当前一致；
4. LKG 年龄 `<= max_age + degraded_grace`（边界包含，`>` 即拒绝）。

**硬拒绝**（即使有 LKG 且落在窗口内）：`NO_DATA`（从未成功采集）、
`INCOMPLETE`（本轮快照结构不完整）、`EXTERNAL_PROVIDER`（未经新鲜度校验）、
外部代次变化、接口身份变化、宽限耗尽。对应阶段 A 文档 §7「结构不完整 /
代次失效仍严格 fail-closed」。

降级时 `stale_for = max(0, lkg_age - max_age)`、
`grace_left = max(0, window - lkg_age)`，用于阶段 C 的限次/冷却与可观测性。

## 6. 安全契约（本阶段最重要的不变式）

- **不改变 `trusted`**：`DEGRADED` 仍 `trusted=False`；
- **不改变 `reason` / `detail` / `reason_text`**：既有日志与告警文案逐字不变；
- **不改变 `snapshot` 字段语义**：`snapshot` 仍是当前发布的快照，LKG 单独放在
  `lkg_snapshot`；`_full_snapshot()` 因 `trusted=False` 仍返回 `None`，
  `_build_failover_snapshot()` 仍回退轻量占位快照；
- **不改变单一副作用门**：`TrayFailoverBridge.set_snapshot_trust(False, ...)`
  仍换成 `RefusingExecutor`，`attempted=False / executed=False` 对所有
  `OpKind` 成立（新增用例逐项验证）；
- **`observe()` 零行为变化的拆分**：原有五维判定整体搬入纯静态方法
  `_classify()`，逐字保留；阶段 B 只在其后增加 `_grade_untrusted()` 后处理。

   ≥180 s 冷却；依据取 `ObservationResult.mode` 与 `usable_snapshot`。
