**语义归纳（实施口径）**

- 需求1「真假死」：**已连上网络 ≠ 真的能上网**。用户遇到的假死形态是「Wi-Fi 显示已连接、
  整机卡顿、部分浏览器/应用可用（走了代理）、另一部分不可用」——即**直连路径**实际不通。
  故「连接后校验」必须走**绕过系统代理的直连路径**，并做**真实抓取 + 内容结构校验**，
  而不是只看 TCP 能连上。
- 需求2「UU 远程」：即**网易 GameViewer**（本机实测进程族 `GameViewer.exe` /
  `GameViewerLauncher.exe` / `GameViewerServer.exe` / `GameViewerHealthd.exe`，
  Windows 服务 `GameViewerService`，自启项 `HKCU\...\Run\GameViewer --auto-run`）。
  网络断开→恢复后其客户端会卡在「正在重新连接」，需**清退后台并重启**。

## 2. 需求1 方案：`verify_internet` 连接后真实上网校验

### 2.1 判据（默认取用户建议的「严格档」）

| 角色 | 站点 | 期望结构 | 校验方式 |
|---|---|---|---|
| **闸门**（必须命中） | `http://www.baidu.com/` | `<title>百度一下，你就知道</title>` | 跟随重定向后 200 + `<title>` 精确匹配 |
| 交叉 1 | `http://www.qq.com/` | `<title>腾讯网</title>` | 同上 |
| 交叉 2 | `http://www.163.com/` | `<title>网易</title>` | 同上 |
| 交叉 3 | `http://www.sohu.com/` | `<title>搜狐</title>` | 同上 |

**通过条件**：闸门命中 **且** 交叉站点命中数 **≥ 2**。

> **取证依据（2026-10-16 真机只读实测）**：上述四个站点**裸 URL 全部 3xx 跳转**
> （百度 302 / 腾讯 302 / 搜狐 301），`allow_redirects=False` 下拿不到正文标题；
> 跟随重定向后均为 **200** 且标题如上表。因此本校验**必须跟随重定向**，
> 与 `DEFAULT_PROBES`（严格 `allow_redirects=False` + 固定标记文本）是**两套不同用途**的探测：
> - `DEFAULT_PROBES` = **低成本高频**「在/离线」探测（每 `interval` 一次）；
> - `verify_internet` = **一次性**「连上之后是否真的好用」深度校验（仅在**连接事件**后跑）。

### 2.2 触发点（只读、零副作用）

1. `watch`：进程内**首次**判在线时执行一次；之后每次「离线 → 在线」跃迁再执行一次。
2. 托盘 `_probe_tick`：每个**在线段**（判为在线 → 判为离线为止）校验一次，离线时重置标记；
   **另在 `_after_repair(ok=True)`（重连成功）单独触发一次** —— 该路径直接把状态置为
   online、不经过 `_probe_tick` 的跃迁，只在跃迁处触发会漏掉「重连成功」这一核心场景
   （实现期发现并已用回归锁定）。校验在**独立短命线程**中执行并用**专用 Session**，
   绝不阻塞监测/重连工作线程。
3. 手动：`verify` 子命令（只读，便于随时自检；未通过退出码 1）。

**覆盖有线/无线**：校验使用默认路由上的直连会话（`direct_session()`，`trust_env=False`），
即「当前真正承载流量的那条链路」——有线时为以太网、无线时经 SNNU，满足
「不管有线还是无线都要测」。

### 2.3 失败时的行为（**不**制造环路）

- 只**记录日志 + 托盘通知**（「已连接但上网校验未通过（疑似假死）：<明细>」）；
- **不**立即触发重认证（避免与 `cooldown` 冲突、避免假死时反复重登）；
- 下一次正常监测周期若 `internet_ok` 判离线，仍按既有阈值/冷却逻辑处理（三层计时器不变）。

### 2.4 接口

```python
verify_site(session, spec, timeout=VERIFY_TIMEOUT) -> ProbeResult   # 单站：跟随重定向 + 结构匹配
verify_internet(session, *, gate=VERIFY_GATE, cross=VERIFY_CROSS,
                min_cross=VERIFY_MIN_CROSS, timeout=VERIFY_TIMEOUT) -> Tuple[bool, str]
```
返回 `(是否通过, 明细)`；明细含每个站点的 `host(ok/错误类型/状态码)`，供日志与通知
（同 F75-13③ 风格）。**本函数不抛异常**（异常一律转成该站失败）；日志由调用方
（`watch` / `_verify_after_connect` / 托盘通知）负责，故接口不再传 `log`。

## 3. 需求2 方案：确认在线后清退重启 UU 远程（GameViewer）

### 3.1 复用既有 P7 远控设施（不新造轮子）

- `campus_remote.DEFAULT_REMOTE_CLIENTS` **新增** `gameviewer` 规则
  （`patterns=("gameviewer", "uuyc")`），使 P7 远控探测/敏感期逻辑认识 UU 远程；
- 新增 `campus_remote_app.py`：**只负责「识别 + 清退 + 重启用户态进程」**这一件事。

### 3.2 范围（用户 Q3 推荐档 = A）

| 对象 | 默认动作 |
|---|---|
| `GameViewer.exe`、`GameViewerLauncher.exe`（用户态） | **清退**后重新启动（经 launcher） |
| `GameViewerServer.exe`、`GameViewerHealthd.exe`（服务子进程） | **不动**（随服务生命期） |
| `GameViewerService`（Windows 服务） | **不动**（重启服务需管理员 UAC，属危险操作黑名单外的显式授权项） |

### 3.3 安全边界（叠加 AGENTS §6）

- **默认关闭**：`remote_restart_enabled = False`；不主动调用即无任何副作用。
- **冷却**：两次真实清退间隔 **≥ 300s**（`remote_restart_cooldown`），落在 `tray_config.json`。
- **退出码/失败如实报告**：进程清退失败、启动器缺失时**如实报错**，不静默重试。
- **真机执行需二次确认**：实现阶段只交付**代码 + 离线测试 + CLI 手动入口**；
  在本机真实清退 UU 远程前，须用户**当面**确认（避免切断用户正在进行的远控会话）。
- 不触碰 Clash / TUN / 系统代理（需求2 与代理无关）。

### 3.4 接口

```python
# campus_remote_app.py
GAMEVIEWER_USER_PROCESSES = ("GameViewer.exe", "GameViewerLauncher.exe")
GAMEVIEWER_SERVICE = "GameViewerService"

@dataclass class RemoteAppStatus: ...          # 只读：进程/服务/自启项
def discover(runner) -> RemoteAppStatus        # 只读
def restart_user_app(runner, *, status=None) -> RestartResult   # 有副作用（显式调用）
```
CLI：`remote-app --status`（只读） / `remote-app --restart`（显式清退重启）。
托盘：设置面板开关（默认关）+ 确认在线后按冷却触发。

**本阶段的关键安全设计（每条都有对应单测）：**

1. **只动用户态两进程**（`GameViewer` / `GameViewerLauncher`）；`GameViewerServer` /
   `GameViewerHealthd` / `GameViewerService` 一律不动；
2. **没在跑就不动**（`action=noop`）——不替用户把已关闭的 UU 启动起来；
3. **找不到重启命令 ⇒ fail-closed**：一个进程都不清退（避免"清退了却起不来"）；
4. **清退失败立即中止**且不启动新实例（避免两个实例抢会话）；
5. **启动失败如实报告**（`action=failed` + 明细），不静默重试；
6. **冷却 ≥300s**（`remote_restart_cooldown`，限幅 60..3600s），跨在线段生效；
   仅**真正完成**的重启计入冷却（失败不计，否则"失败一次等 5 分钟"）；
7. 清退/重启全程**不经 shell**（`taskkill /PID <pid> /F`；启动用 `posix=False`
   切分命令行 —— 真机自启项 `"C:\_study\GameViewer\GameViewer.exe" --auto-run`
   若按 POSIX 规则会被吃掉反斜杠）。

**已知取舍（记录在案，非缺陷）**：`RestartGuard.last_at` 只在进程内保存，故**托盘重启会重置冷却**；
冷却用于抑制同一运行期内的连环触发。若"启动失败"，UU 会停在已清退状态（气泡如实提示），
需用户手动或自启项拉起——本阶段不引入自动重试，避免与远控会话互相踩。
