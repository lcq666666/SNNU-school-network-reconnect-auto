## 0. 范围界定说明

现行执行计划**仅详列 P0**，P5 只有 §0.2 的行级定义：

> **P5 受控路由切换与路由卫士**：新增 `campus_route_guard.py`，快照/切换/验证/回滚；
> 允许真实副作用（受控、单人值守）；前置依赖 P4。

本阶段据此行定义，叠加以下五处权威约束确定范围（与 P2/P3/P4 的处置方式一致）：

1. 主方案 §7.2「路由变更需要事务和回滚」：每次切换前保存（目标网卡标识、原始接口 Metric 与
   自动 Metric 状态、原始默认路由及 RouteMetric、IPv4/IPv6 相关配置、当前主路径、变更的**唯一
   操作编号**）；**先条件校验 → 再应用最小变更 → 随后检查结果**；须有**独立于主监控线程**的
   本机恢复机制；**回滚不得简单"永远恢复到有线优先"**；
2. 主方案 §4.2 阶段 B：保存快照 → 重新确认前置条件 → 调整 Metric 使目标接口优先 → **验证
   Windows 实际选择的出口已改变** → 标记接管 → 记录原因/耗时/结果；**建议用可逆的优先级调整，
   不通过禁用 Ethernet 强行切换**；
3. AGENTS §3.7：**先证实再切换** —— IPv4 与 IPv6 默认路由**都要检查**，不得只切 IPv4；
4. AGENTS §3.11/§3.12：路由/Metric 修改集中到独立 Windows 适配层、权限缺失时提示而非重试；
   危险操作黑名单（禁用/重置网卡、删除全部默认路由、清空 DNS、重启网络服务、断开全部连接、
   强杀远控、改 Clash TUN/代理）在本阶段**无任何入口**；
5. P3 冻结的执行器协议（P3 报告 §6）与 P4 契约：`METRIC_WRITE` / `CLASH_TOUCH` 由 P5 落地；
   `SnnuBackupExecutor` 只实现 `PORTAL_POST` / `WIFI_RECONNECT`，P5 需组合为**单一执行器**。

**不越界声明**：P5 不改动托盘三模式界面（P6）、不实现远程会话敏感期延迟切回与远控探测（P7）。
P5 提供 `--auto` 受控入口以**启用** `FailoverMode.AUTO`（P3 报告 §9.3 指定属 P5），但**默认关闭**，
须 `--yes` 显式授权并前台上人。
