# V0.6.7 恢复与更新

正式发布版本为 v0.6.8。迁移配置、自启重定向和自动锁屏仅在打包 EXE 入口执行，源码调试与启动回归测试隔离这些系统写入。v0.6.7 标签构建已停止。

用户确认四位纯数字验证码，并允许在故障恢复中强制重启，接受未保存文件丢失。两台设备均有 Windows 登录密码。

## 实现范围

- 配置固定保存在 `%LOCALAPPDATA%\CampusReconnect\tray_config.json`，首次运行迁移 EXE 同目录配置或旧自启路径的配置，保留迁移备份。旧自启项随新版启动迁移路径。
- “下载更新”在本地弹窗显示进度，下载指定 Release 的 EXE 与 SHA256 文件。校验摘要与发布大小后启动独立替换器，等待旧进程退出，替换并启动新版。新版启动回执版本不匹配或超时则回滚旧 EXE。
- 更新检查支持 GitHub API，API 失败时尝试 Release 的 `build_info.json`，使用当前系统代理访问 GitHub。
- 四位数字验证码使用本机 CPU OCR。图片、隐藏字段和登录提交复用原认证会话，仅允许相同源的已知登录动作。一次认证至多两次提交，失败后按恢复冷却继续检测。
- 三层恢复为独立控制器，使用持续公网与 UU 外部 TCP 连接观测。30 秒持续故障后重启 UU，等待 60 秒后执行代理备份、关闭代理、重连认证、恢复代理和重启 UU。
- 故障持续 15 分钟且用户已允许重启、开机自启与自动登录配置可读时，安排 60 秒后的强制重启。同机六小时最多一次。恢复正常、暂停或关闭恢复时撤销尚在进行的重启倒计时。
- 代理变更前持久保存原值和注册表类型，正常结束时恢复，进程中断后的下一次启动首先尝试恢复。三层恢复开启时由该控制器独占自动恢复操作，旧故障切换逻辑保留只读快照供展示。
- Windows 自动登录通过微软官方 Autologon 本地设置入口配置。下载后验证 Microsoft Authenticode 签名，账户密码由用户在官方窗口输入。工具使用 LSA 机密，管理员可能读取。三层恢复开启后的开机自启会锁定屏幕。

## 开关与授权

发布默认关闭 `lifeline_enabled` 与 `lifeline_reboot_enabled`。设置 → 恢复可以启用。启用强制重启时说明文件丢失风险并在本机确认。Windows 自动登录需用户在本机完成并做一次重启验收。

## 验收

- Windows 发布使用 Python 3.12 和 ddddocr 1.5.6。1.6.1 在本次用户提供的截图上出现误读，因此采用已通过该样本检查的识别实现与其支持的运行时。

- 离线回归覆盖三层阶段、代理异常恢复、跨进程重启频率、恢复后取消倒计时、稳定配置迁移、同会话验证码提交、重试上限、跨源拒绝、下载校验和本地更新弹窗。
- 本机合成四位数字图片通过 OCR，真实校园网验证码图像与真实离线认证仍待现场验收。
- Windows 自动登录、锁屏、电脑重启后 UU 控制端连通性需两台设备分别验收。UU 外部 TCP 已建立代表存在连接证据，控制端实际远控连接结果另行确认。
- 黑屏死机的系统根因仍未定位。持续系统死机期间，进程内恢复程序无法运行。
