## 2. 关键修改文件与逻辑

### 2.1 新增 `campus_tray_observer.py`（纯逻辑，零副作用）

- **`SnapshotProvider`**：后台三轴快照采集调度器。
  - 单飞采集：任何时刻仅一个后台采集在进行，避免 PowerShell 堆积。
  - 采集超时：默认 12s，超时后观测结果为 `SNAPSHOT_COLLECT_TIMEOUT`。
  - 单调时钟新鲜度：`collected_at` 用 `time.monotonic()`，最大有效期 8s。
  - 代次管理：配置改变 / SSID 改变 / DHCP 变化时代次 `+1`，旧快照立即失效。
  - 并发限流：最小采集间隔 3s，防止高频 tick 触发连续诊断。
  - 完整度校验：快照必须含 `recommendation` + `generated_at` + 至少一个接口轴。
- **`ObservationResult`**：结构化观测结果，含 `trusted/reason_text/generation/age/is_complete`。

### 2.2 修改 `campus_tray_failover.py`

- 新增 `SNAPSHOT_*` 常量（7 种不可信原因）。
- `TrayFailoverBridge` 新增：
  - `set_snapshot_trust(trusted, reason)`：AUTO 在 tick 前由托盘设置可信度门禁。
  - `snapshot_trusted / snapshot_reason`：供状态机决策与 UI 展示。
- `_decide` 中 AUTO 分支：数据不可信时直接 `return TickResult(state)`，零副作用。
- `tick()` 返回 `TickResult`（原已返回，但桥接处现在确保不可信时短路）。

### 2.3 修改 `campus_reconnect_tray.py`

- **快照构建重构**：
  - 删除 `_failover_snapshot_provider = None` 的缺省轻量回退。
  - 新增 `_snapshot_source()` → `SnapshotProvider` 工厂。
  - 新增 `_full_snapshot()`：异步采集完整三轴快照，更新 `last_observation`。
  - `_build_failover_snapshot()` 改为优先读取 `last_observation`，可信时返回完整快照，否则回退 `light_snapshot`（仅 UI 占位）。
- **_failover_tick 可信度门禁**：
  - tick 前读取 `last_observation.trusted`。
  - 不可信时调用 `bridge.set_snapshot_trust(False, reason)` 并记录日志。
  - 返回 `TickResult` 供调用方使用。
- **_probe_tick 模式隔离（F75-02）**：
  - 删除达阈值后调用 `_run_repair()` 的旧 V0.2 自动认证路径。
  - 替换为：按模式显示不同说明（AUTO → "已交由故障切换调度器"；MONITOR → "仅监测，不自动认证"；LOCKED → "手动锁定，可手动重连"）。
  - 探测与认证完全解耦：探测节奏恒 `now + interval`，认证冷却只门控 `_run_repair`（现在仅手动重连触发）。
- **_dispatch 版本校验**：
  - 手动重连命令携带请求时的 `config_version`。
  - 若期间模式/配置已变更，直接丢弃过期请求。
- **_enqueue_repair**：保留但增加版本号投递。
- **同步配置到桥接**：`update_config` 和 `apply_mode` 时更新桥接模式并重新评估执行器接线。
