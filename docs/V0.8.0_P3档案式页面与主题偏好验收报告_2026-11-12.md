## 附：黑色命令框闪现排查结论（本轮只排查，未修改）

**结论：是，本软件存在明确且可复现的致因路径。** 证据链：

1. `CampusReconnect.spec` 为 `console=False`（GUI EXE，本身不显示控制台）。
2. `campus_reconnect.py:857-864` 的 `_run_console()` 执行 `netsh wlan show interfaces`、`ipconfig` 等，`subprocess.run` **未设置** `creationflags=CREATE_NO_WINDOW`；`campus_reconnect.py:919` 的 `netsh wlan connect` 同样没有。`git show v0.6.10:campus_reconnect.py` 与 `v0.7.0` 完全一致，说明当前运行版本也带此问题。
3. `campus_reconnect_tray.py:2980`（`_wifi_bringup._Ops.run`）的 `subprocess.run` 同样未设置窗口隐藏标志。
4. Windows 机制：GUI 进程启动控制台子进程时，若未指定 `CREATE_NO_WINDOW` / `STARTUPINFO` 隐藏，系统会新建 `conhost` 窗口，表现为黑框闪一下。
5. 其余运行时 PowerShell/子进程调用（`campus_windows.py:760`、`campus_route_guard.py:1080`、`campus_auto_setup.py`、`campus_boot.py`、`campus_update_install.py`、`campus_resilience_windows.py`）**均已带** `CREATE_NO_WINDOW`，可见遗漏集中在 CLI/托盘共用的 `_run_console` 与 Wi-Fi bringup 两处。
6. 进程快照显示当前运行的是两个 `outputs/v0.6.10/CampusReconnect.exe`（PID 38148 / 45832），日志每 5 秒一次 failover 探测、并有周期性配置核对，具备「过一段时间闪一下」的触发节奏。

同时发现**其他软件也可能闪框**：Codex / 浏览器扩展的 `cmd.exe`（extension-host、native-messaging）与 `tools/netdiag.py` 的 `Get-DnsClientServerAddress` PowerShell 诊断进程在快照中可见。它们不是本软件主程序，但会增加闪框频率。

**建议的最小修复（未执行，等授权）**：在 `_run_console`、`wifi_reconnect` 的 `subprocess.run` 及 `_wifi_bringup._Ops.run` 加 `creationflags=getattr(subprocess, "CREATE_NO_WINDOW", 0)`，或统一改走 `campus_windows` 已带隐藏标志的执行器。这仅改进程启动标志，不动任何网络/恢复算法，但属于后端文件，故本轮未擅自改动。
