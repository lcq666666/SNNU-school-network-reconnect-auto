### 3.2 T30 全绿；互斥体创建失败时后台认证被拒绝或降级只读

**结论：通过。**

- `tests/unit/test_f18_mutex.py`（T30）：**12 passed**。
- 证据：
  - 大句柄（`0x7FFF_FFFF_0000_1234`，超出 32 位）被完整持有，未被截断（`test_t30_big_handle_is_held`）；
  - `ERROR_ALREADY_EXISTS` 路径**及时 `CloseHandle`** 新句柄（`test_t30_already_exists_closes_new_handle`）；
  - `NULL` 句柄 / `ACCESS_DENIED` / DLL 异常 ⇒ `failed_closed` 且 `error_code == E_MUTEX_FAILED`
    （`test_t30_null_handle_fails_closed`、`test_t30_access_denied_fails_closed`、`test_t30_create_exception_fails_closed`）；
  - `release()` 仅 `CloseHandle`，**未**使用 ownership（假件未定义 `ReleaseMutex`，未抛 AttributeError）；
  - 真实 `kernel32` ABI 断言：`CreateMutexW.argtypes == [LPVOID, BOOL, LPCWSTR]`、`restype is HANDLE`
    （`test_t30_real_kernel32_declares_abi`，仅 Windows 执行）；
  - `once` 认证拿不到互斥体 ⇒ 退出码 1（`test_t30_once_refuses_when_mutex_unavailable`）。

**代码依据**：`campus_windows.SingleInstanceGuard`（显式 ABI、可关闭句柄、fail-closed）；
`campus_reconnect.ensure_single_instance`（fail-closed）；`main()` 中 `once` 获取互斥体。
互斥体名不含 `Global\` 前缀 ⇒ 作用域为**每 Windows 会话**。

### 3.4 文档每处网络目的、系统写入、支持范围都能在代码/测试中找到依据（F24）

**结论：通过。**

| 文档条目 | 实现/测试依据 |
|---|---|
| 顺序尝试两个探测点、首个成功即返回 | `campus_reconnect.probe_online`（顺序循环，任一 `ok` 即在线）；`internet_ok` |
| 网络目的：Portal + 公开探测（Microsoft/Apple）；不上传账号给作者/云端；可能暴露源 IP | `DEFAULT_PROBES`；`direct_session`（`trust_env=False`）；无任何上传代码 |
| 代理：CLI 默认不动、托盘经授权才写、仅本机端点、注册表写成功≠立即同步 | `ProxyController.apply`（先读快照→验证端点→最后写 `ProxyEnable`，事务回滚）；`validate_proxy_endpoint`；`default_refresh` 单独报告 |
| 凭据：经 Windows 凭据管理器读写、非“完全不落盘” | `CredentialStore`（load/save/clear）；`Secret`（`repr` 脱敏） |
| 同账号其他设备影响取决于学校并发策略 | 文档限定表述（不再作绝对保证）；程序不执行 logoff |
| 学校专用 Portal，改 SSID 不自动适配其他学校 | `PORTAL_IP`/`KNOWN_PORTS`/`LOGIN_JSP` 等常量；`_is_portal_url` 白名单 |
| SSID 需完整匹配（含大小写/空格） | `_ssid_matches` 完整比较；`test_t29_case_difference_is_not_target` |
| 任务计划步骤无重复、无“最高权限”建议 | README §7 已修订 |
